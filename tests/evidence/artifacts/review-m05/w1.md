## Finding

### M05-W1-R01 — High / blocking: trust approval substitutes an unreviewed Git common-directory identity

**Evidence:** [crates/app/src/operations/trust_m05.rs:1401](crates/app/src/operations/trust_m05.rs:1401) and [crates/app/src/operations/trust_m05.rs:1739](crates/app/src/operations/trust_m05.rs:1739). The initial decision records `git_common_identity` in its basis at [crates/app/src/operations/trust_m05.rs:1020](crates/app/src/operations/trust_m05.rs:1020). `check_trust` ignores that field, checking only root path, root identity, access digest and environment. `apply_trust` then persists the approval-time common identity through `observed_git.or(git_common_identity)`. In contrast, reconcile compares the common identity with its recorded basis at [crates/app/src/operations/trust_m05.rs:1490](crates/app/src/operations/trust_m05.rs:1490).

**Concrete scenario:** request trust for an existing checkout and leave the decision pending. Before approving it, the owner replaces/reinitializes its Git directory while preserving the working directory and manifest. The new Git repository can have valid linked worktrees outside that root. Approving the old decision succeeds and stores the **new** Git common-directory identity. Those linked worktrees now match `Member` through [crates/project/src/matching.rs:47](crates/project/src/matching.rs:47), although their common directory was absent from the decision's basis. This differs from changing Git directories after approval, which leaves the stored common identity unchanged.

This is lasting local workspace authority applied beyond the decision's recorded basis, violating ADR-0011 I5 and §2.3. It requires an owner's Git operation, not a hostile same-user program. That meets ADR-0009 §2.1's consent-bypass classification. W1's runtime has no native workspace observer installed yet; the defect is reproduced through the production authority core's `WorkspaceProbe` port, and becomes a user-facing path when U4 supplies that observer. It should be fixed in the authority core before that integration.

**Probe:** append [review-out/trust-common-probe.rs](review-out/trust-common-probe.rs) to `tests/model/trust_policy.rs`, then run:

```sh
cargo test --locked -p heimdall-runtime --test model_trust_policy review_trust_rejects_changed_git_common_identity
```

Observed on unchanged production source: **exit 101**, one assertion failure. Before its final expected-refusal assertion, the probe verifies that the original basis holds common identity `101`, approval succeeds after the observer changes only that identity to `999`, and the saved workspace holds `999`. A temporary comparison of the observed and recorded common identities makes the same probe **exit 0**. Both that temporary comparison and the appended test were undone. The first attempt to combine matching and authority in this test failed to compile because runtime has no direct project dependency (exit 101); the corrected probe above was compiled and executed, so the finding does not rely on that build failure. Structured outcomes: [review-out/trust-common-results.json](review-out/trust-common-results.json).

A separate disposable **real Git** fixture, [review-out/git-common-fixture.py](review-out/git-common-fixture.py), ran with **exit 0** and asserted all four facts: root identity unchanged; manifest bytes unchanged; Git common-directory identity changed; the new linked worktree's backlink valid. It used only a temporary home and local repositories and deleted them afterward. This establishes the filesystem scenario; it is not a native Heimdall-observer test.

**Smallest correction:** include optional Git common-directory identity in the trust approval's basis equality, including appearance/disappearance, and persist the recorded identity. A mismatch should leave the decision pending and require review again, as reconcile already does. Extend the existing trust-observation regression with this one mutation. No fix is retained in this review checkout.

## 1. Authority answers

- **Unattended widening:** except for R01's substitution during an attended approval, I found no independent path that writes new/wider authority without an attended owner decision. The application checks owner role before policy dispatch ([crates/app/src/operations.rs:11054](crates/app/src/operations.rs:11054)) and checks both attendance and owner role before `decide` ([crates/app/src/operations.rs:11239](crates/app/src/operations.rs:11239)). `classify` separates immediate narrowing from widening ([crates/app/src/operations/trust_m05.rs:395](crates/app/src/operations/trust_m05.rs:395)); approvals apply the recorded action transactionally ([crates/app/src/operations/trust_m05.rs:1521](crates/app/src/operations/trust_m05.rs:1521)). Trust compares the caller's digest/proposal with the server-built proposal ([crates/app/src/operations/trust_m05.rs:921](crates/app/src/operations/trust_m05.rs:921)). Reconcile requires the same recorded root/identity/common directory, marks the old record stale and creates a new one ([crates/app/src/operations/trust_m05.rs:1814](crates/app/src/operations/trust_m05.rs:1814)).
- **Clones/copies/moves/worktree tricks:** canonical path plus root identity establishes direct trust; same-path replacement and same-identity move are ambiguous. Clones, copies, cross-filesystem moves and nested repositories do not inherit trust. Membership requires canonical resolution of `.git`, the `worktrees/<entry>` shape, backlink path **and** identity equality, and a stored common-directory identity match ([crates/project/src/observe.rs:257](crates/project/src/observe.rs:257), [crates/project/src/matching.rs:35](crates/project/src/matching.rs:35)). Relative pointers, `..`, stale backlinks, copied worktrees and submodules are covered by the 40 passing project tests ([tests/model/project_pure.rs:1375](tests/model/project_pure.rs:1375)). R01 concerns which common identity gets saved, not a bypass of these membership checks.
- **Repository file as approval instruction:** no executable hook or approval field is accepted. The parser scans authority vocabulary before decoding the closed schema ([crates/project/src/manifest.rs:221](crates/project/src/manifest.rs:221)); labels are bounded, control-stripped data ([crates/project/src/manifest.rs:178](crates/project/src/manifest.rs:178)). The authority core independently builds proposals and actions; repository values never supply `Decide` or its title/action. Native observer, shell-hook and final review UI integration remain later-wave work.
- **`extend_scope`, coalescing and cooldown:** requested additions must fit the local profile and managed environment set. Widening queues a decision. Exact added actions coalesce at the current generation; a broader action cannot join a narrower one ([crates/app/src/operations/review_m05.rs:113](crates/app/src/operations/review_m05.rs:113)). Denial records per-key cooldowns; a revision change clears obsolete cooldowns ([crates/app/src/operations/review_m05.rs:222](crates/app/src/operations/review_m05.rs:222), [crates/app/src/operations/trust_m05.rs:208](crates/app/src/operations/trust_m05.rs:208)). The decision-budget model exercises concurrent callers and deny/approve/expiry, and passed (exit 0).
- **`covered_only`:** absent context is rejected with `USAGE_ERROR` before reads/writes; with context it currently fails closed with `driver_unavailable` ([crates/app/src/operations.rs:9425](crates/app/src/operations.rs:9425)). P9 proves that refusal creates no decision; it does **not** prove covered-subset activation, which is U4/W2. The pure coverage function keeps the policy's recorded lock behaviour ([crates/domain/src/policy.rs:430](crates/domain/src/policy.rs:430)).
- **Fresh work IDs versus pause/cutoff:** no bypass found. The resolver checks blocks before intersection or approval ([crates/domain/src/authority.rs:193](crates/domain/src/authority.rs:193)), and activation checks the current context's blocks ([crates/app/src/operations.rs:2148](crates/app/src/operations.rs:2148)). Executed `model_operations r136_1_`: **exit 0, 4 passed**, including fresh request/work IDs and delegation under pause/cutoff ([tests/model/operations.rs:3421](tests/model/operations.rs:3421), [tests/model/operations.rs:3522](tests/model/operations.rs:3522)). Existing same-key replay is intentionally distinct from new activation.
- **Workspace policy reaching personal/another workspace:** no scope, lock or connection-policy leak found. `applicable_policies` filters by context, and `resolve_policy` merges only applicable blocks ([crates/domain/src/policy.rs:216](crates/domain/src/policy.rs:216)). Personal blocks apply to that profile's workspace work; the reverse does not. Executed the two-policy property (**exit 0, 1 passed**), personal resolution with a first-by-ID hostile workspace policy (**exit 0, 1 passed**), and the workspace-lock isolation regression (**exit 0, 1 passed**). Context and grant-policy reads are centralized in [crates/app/src/policy_context.rs:1](crates/app/src/policy_context.rs:1).

## 2. Hostile-input answers

- **Authority keys, size and depth:** accepted manifests cannot contain authority keys at any accepted depth, including metadata and tables in arrays. Names are whole-key, ASCII case-insensitive with hyphen normalization. `preferences.background_work` is the single boolean exception. Input is bounded to 64 KiB before TOML parsing; nesting depth is at most 4; access lists at most 256; tokens at most 128 bytes. Duplicates, raw NUL and invalid UTF-8 are refused ([crates/project/src/manifest.rs:221](crates/project/src/manifest.rs:221), [crates/project/src/manifest.rs:287](crates/project/src/manifest.rs:287), [crates/project/src/manifest.rs:361](crates/project/src/manifest.rs:361)). The authority scan stops descending at 64, but such a file is already invalid by depth; it is not accepted. Project tests include arbitrary bytes, authority key placement/casing, nesting bombs and inclusive bounds; **exit 0, 40 passed**.
- **Symlink/FIFO/swap/hash consistency:** the pure implementation asks `FsView::read_regular_nofollow` for one bounded regular-file read, then parses and hashes the returned buffer ([crates/project/src/observe.rs:73](crates/project/src/observe.rs:73), [crates/project/src/observe.rs:182](crates/project/src/observe.rs:182), [crates/project/src/manifest.rs:254](crates/project/src/manifest.rs:254)). It has no second path read that can hash different content. A non-UTF-8 canonical root is refused before reading the manifest ([crates/project/src/observe.rs:179](crates/project/src/observe.rs:179)). The memory filesystem tests check nonregular entries and single-read behaviour. **Native no-follow open, FIFO nonblocking handling, swapped-file races and non-UTF-8 filesystem paths are not proven by W1**: there is no native `FsView` implementation in this wave. The real cases are explicitly U4/W2 obligations; these tests cannot close them.
- **Portable bundle authority refusal:** the parser recursively refuses known authority keys, rejects every unknown top-level section and closes every nested destination/identity/profile object before typed decoding ([crates/project/src/portable.rs:168](crates/project/src/portable.rs:168), [crates/project/src/portable.rs:281](crates/project/src/portable.rs:281)). A missing vocabulary synonym cannot become an accepted arbitrary authority section because those schemas are closed. Size is capped at 1 MiB and the JSON walk at 64 levels. Emission constructs catalog intent only. The passing project suite includes bundle round trips, redaction and injected authority sections. The actual import transaction/preview is U7 and still refused in [crates/app/src/operations/portable_m05.rs:1](crates/app/src/operations/portable_m05.rs:1); this review does not claim to have tested that future transaction.

## 3. Shared-slot answer

The built claim matches ADR-0011 §10 item 6. Joining records a reference without changing the materializer's files, generation or pins ([crates/app/src/operations/slots_m05.rs:137](crates/app/src/operations/slots_m05.rs:137)). A slot write obtains the attached materializer grant's public key and certificate for exactly that pair ([crates/adapters/src/managed/effects.rs:495](crates/adapters/src/managed/effects.rs:495)); sibling scopes/deadlines are not unioned into a certificate. Cleanup drops unusable references, frees when none remain, otherwise selects the latest-deadline usable referencer and claims the next generation transactionally ([crates/app/src/operations/slots_m05.rs:269](crates/app/src/operations/slots_m05.rs:269), [crates/app/src/operations/slots_m05.rs:319](crates/app/src/operations/slots_m05.rs:319)). Runtime re-materialization uses that binding's own grant ([crates/runtime/src/slot_handover.rs:44](crates/runtime/src/slot_handover.rs:44)).

The live `two_jobs_share_a_pair_and_hand_over` journey ([crates/runtime/src/managed_store/live_tests/slots_m05.rs:342](crates/runtime/src/managed_store/live_tests/slots_m05.rs:342)) checks the exact installed certificate, accepted SSH key before/after handover, stale generation cleanup, unchanged pins and last-reference cleanup. It passed within the **36 passing managed-runtime live tests, exit 0**. A04 and A16's native/two-managed-environment realization also passed. This does not claim WSL/container interoperability. Shorter siblings' ordinary alias is deliberately shared; the returned `shared_environment_default` label and warning describe that limit ([crates/app/src/operations/slots_m05.rs:234](crates/app/src/operations/slots_m05.rs:234)). Re-materialization failure leaves an unavailable alias, a fail-closed limit rather than excess authority.

## 4. Delegation / A28 answer

The child endpoint lists only its own certificate(s), refuses control and issuance frames, and does not confer owner role. Broader/later delegation is refused before child key creation. The five live A28 cases test two real loopback servers with distinct principals under the same fixture CA, wider/longer refusals, endpoint/control separation, parent-end cascade and existing-access convenience labels ([crates/runtime/src/managed_store/live_tests/delegation_m05.rs:315](crates/runtime/src/managed_store/live_tests/delegation_m05.rs:315), [crates/runtime/src/managed_store/live_tests/delegation_m05.rs:507](crates/runtime/src/managed_store/live_tests/delegation_m05.rs:507)). All passed within the runtime run, **exit 0**.

**A same-OS-user child can still derive/open the owner's control endpoint itself.** Its OS identity may then have owner capabilities; it has not been sandboxed or assigned a separate OS principal. This is the documented R1/P03 limit, not a new bypass through the child binding. Existing-access keys have the declared client-routing/shared-user convenience limit; server attenuation is proven only for the managed-principal recipe. `owner_functions: not_delegated` and `workload_isolation: shared_os_user` correctly retain that distinction ([crates/app/src/operations/narrowing.rs:1209](crates/app/src/operations/narrowing.rs:1209)).

`run --parent-binding` removes captured `HEIMDALL_*` control/home variables, replaces `SSH_AUTH_SOCK` with the child's endpoint or unsets it if none is set, and the launch layer applies the removals ([crates/heimdall/src/delegate_cmd.rs:303](crates/heimdall/src/delegate_cmd.rs:303), [crates/launch/src/env.rs:155](crates/launch/src/env.rs:155)). The real CLI test launches a worker and verifies those environment names, distinct child endpoint, child-only listing, admitted login and refused other principal. **`e2e_delegation_m05`: exit 0, 4 passed.** This proves the supported fixture workflow, not a general environment-secret scrubber or OS isolation.
