Reviewer: the single independent review under ADR-0009 §2.1. Detached worktree at `3943738d`; no

## Verdict: MERGE WITH FIXES

**No finding blocks under ADR-0009 §2.1.** A finding blocks only if it has a lasting effect on
remote trust, recovery records or the owner's data, or bypasses consent, *and* its trigger is one
Heimdall must withstand. None of the findings below has the first property:

- **The installers** still delete nothing they did not create, and act only on their own names in
  the prefix. The gaps produce a mismatched `.previous` pair (which the hello refuses, as W1
  recorded for R04) or an update that goes ahead beside a live old process.
- **`crates/stategen`** still has no dependents, so no product path reaches it. Its W2 changes are
  correct.
- **The iroh bypass** needs the release builder to pass an unusual feature spelling. It affects a
  build record and a release policy, not remote trust or the owner's data.
- **The fuzz accounting gap** and the record lines affect records, not recovery records or data.

**Fix before the candidate (U3b):** R01, R02 and R03, each with its regression. Also correct the
records in R05, because two of them claim closures that do not hold.

## Findings

### M08-W2-R01 (low): R04 is not closed. A staged `.heimdall.new.exe` does not show that rename 3a happened

- **Blocks:** no. Its effect is W1-R04's effect: the older executable beside a newer helper, which
  the hello refuses (ADR-0014 §3.5). Nothing is deleted. The trigger is ordinary (a lost
  executable, then a kill during the rerun), but the effect is not one §2.1 names.
- **Where:**
  - `tools/packaging/install.ps1:391`: `$interruptedUpdate` needs `cur` absent, `.heimdall.new.exe`
    a file, `prev` a file, `curH` a directory and `prevH` absent.
  - `:417-423`: the finish-move uses that value.
  - `:453`: step 1 stages `.heimdall.new.exe` in every update, including one that starts with no
    current executable.
  - `:481-490`: such a run never does rename 3a; it takes the `elseif` branch.
- **What goes wrong:** a run that starts in W1-R04's own state and is stopped after staging
  (step 1 or 2) leaves exactly the signature the fix reads as "between 3a and 3b". W1-R04's state
  is no current executable, an older `heimdall.previous.exe` without a helper, and the current
  helper. It is the same state the W2-R04 self-test sets up. The stop can be a kill, a closed
  window or a reboot. Antivirus holding the fresh `.heimdall.new.exe` so that the catch block's
  `Delete($new)` throws has the same effect. The next rerun then pairs the newer helper with the
  older executable.
- **Reproduced:** under pwsh 7.7.0 on macOS, with fake archives only (logic, not Windows file
  semantics). The probe is `probes/probe-r04.ps1` and its output `probes/probe-r04.txt`.
  1. Precondition: `cur=<absent> | curH=fake helper 2.0.0 | prev=fake heimdall 1.0.0-nohelper | prevH=<absent>`.
  2. `HM_INSTALL_TEST_STOP_AFTER=1`: exit 1. The state is the same, plus `new=fake heimdall 2.0.0`.
  3. The rerun exits 0 and prints "finished an interrupted update: the previous pair is complete
     under the .previous names". It then prints "the previous pair is kept under the .previous
     names (install.ps1 -Rollback puts it back)". The state is now
     `prev=fake heimdall 1.0.0-nohelper | prevH=fake helper 2.0.0`.
  4. `-Rollback` exits 0, and the result is `cur=fake heimdall 1.0.0-nohelper | curH=fake helper 2.0.0`.
     That is W1-R04's end state.
- **Why the tests pass:** `install-selftest.ps1`'s `W2-R04` cases run that state with no leftover
  staged file. Revert proof `W2-R04` therefore shows only that the presence check helps there.
- **Records to correct:**
  - `tests/native/m08/lifecycle/README.md:226` ("R04 to R07 are closed on Windows");
  - the R04 row at `:205`;
  - the progress row ("an interrupted update is recognised only from the run's own staged
    executable"; "R04 to R07 closed on Windows").
- **Fix:** W1's other option. Write a marker file this script owns just before rename 3a, and
  remove it after 4b. For example, `.heimdall.updating`, checked by `Assert-Names` as a file, and
  holding the staged executable's manifest digest. Decide `$interruptedUpdate` from the marker,
  not from `.heimdall.new.exe`. Add a self-test case that follows the probe's sequence: W2-R04's
  state, `STOP_AFTER=1`, then a rerun with no "finished an interrupted update" and no
  `linux-x86_64.previous`, then `-Rollback` refusing. Its revert proof is the current condition.

### M08-W2-R02 (low): the iroh refusal is bypassed by a whitespace-separated feature list

- **Blocks:** no. It needs the release builder to spell the feature list unusually. The effect is
  an archive that carries the preview transport against ruling E2, with a build record that says
  it does not. That is not remote trust, a recovery record or the owner's data.
- **Where:**
  - `tools/packaging/build-release.sh:51` matches only `,iroh,` and `,heimdall/iroh,` in the
    comma-joined list;
  - `tools/packaging/provenance.py:909` splits on commas only, then takes the last `/` segment;
  - `provenance.py:547` writes `"iroh_transport": "not built …"` unconditionally, whatever was
    built.
  - Cargo reads `--features` as a list separated by spaces or commas.
- **Reproduced:** nothing was built. The script is `probes/iroh-spellings.sh` and its output
  `probes/iroh-spellings.txt`. It runs line 51's `case` on its own and the real
  `provenance.py build-record` against a scratch stage:
  - `iroh` and `heimdall/iroh`: line 51 refuses, and provenance exits 1 "refused: release
    artifacts are built without the iroh feature".
  - `heimdall-runtime/iroh`, `heimdall-transport-iroh/iroh` and ` iroh`: line 51 passes, and
    provenance refuses. This is after the build, with exit 1 rather than the stated "exit 2,
    before any build".
  - `iroh iroh` and `heimdall/iroh iroh`: **both pass**. Provenance goes on to fail only on the
    scratch stage ("the stage holds no executable").
- **Cargo resolves those lists to iroh:** `probes/iroh-cargo-tree.txt`.
  `cargo tree --offline --locked -p heimdall --features "iroh iroh" -e normal --target aarch64-apple-darwin -i iroh@1.4.2`
  prints `iroh v1.4.2 └── heimdall-transport-iroh`. Without features, the same command reports
  that `iroh@1.4.2` matches no package.
- **`build-release.ps1`:** not affected for spaces. Its `^[A-Za-z0-9_,/-]+$` check refuses them.
  `-Features heimdall-runtime/iroh` passes its `-contains` check and is refused only by provenance
  after the build.
- **Fix:**
  1. Split on `[,[:space:]]+` in both scripts and in `provenance.py`.
  2. Refuse any token whose last `/` segment is `iroh`, before the build.
  3. Derive `iroh_transport` from the build rather than stating it: refuse in `build-record` when
     the compiled package set (`compiled_packages` over the build messages, already read for the
     SBOM) holds the `iroh` package.
  4. Add a provenance self-test case for `"iroh iroh"`.

### M08-W2-R03 (low): fuzz time can still be credited to the wrong build after a failed or killed `setup`

- **Blocks:** no. This is a records effect: a stopping-rule claim on code that was not fuzzed for
  the counted time.
- **Where:** `fuzz/run-campaign.sh`.
  - `:94` `setup` replaces `/vol/work/src`, and at `:102` it truncates `built.txt`.
  - It builds target by target and ends with `[ -s built.txt ]` (`:113`).
  - Only after that does it run `BUILD_ID_SCRIPT` (`:117`), which writes `/vol/work/out/build-id`
    last (`:57-67`, the write at `:65`).
  - Nothing removes the old `build-id` first. So a setup that is killed (the 2026-11-22 setup
    was, at 4 GiB, per `fuzz/README.md`'s "Six runs exited 1") or that fails in
    `BUILD_ID_SCRIPT` leaves the **previous** build's identity beside the **new** sources and
    the targets already rebuilt.
  - `run` (`:136-137`, `:147`) tags every line with that old identity. `cargo fuzz run` builds from
    `/vol/work/src`, the new tree.
  - So time on new code counts toward the old build, which is R08(a)'s defect in a narrower form.
- **Also outside the identity:**
  - **The root `Cargo.toml`.** The linked crates inherit `[workspace.dependencies]` from it
    (`Cargo.toml:53`; for example, `crates/ipc/Cargo.toml` has 23 `workspace = true` lines), and
    a dependency feature set there changes the build without changing the lock.
  - **The pins** `NIGHTLY`, `CARGO_FUZZ` and `RUSTFLAGS` (`:29-30`, `:49`).
- **Source:** derived from the code. Not reproduced: no container was run.
- **Fix:**
  1. At the start of `setup`'s container script, before `rm -rf /vol/work/src`, remove
     `/vol/work/out/build-id`, so a setup that does not finish leaves runs tagged `unknown`,
     which the report never counts.
  2. Compute the identity from the copied sources before building.
  3. Add `Cargo.toml` and the three pins to the hashed input.

### M08-W2-R04 (low): `install.sh`'s `-ef` check (R06) misses a live process whose installed executable is gone. W1's string comparison caught it

- **Blocks:** no. The effect is an update installed beside a still-running old runtime, a version
  skew. The old process keeps its state and lock. No trust or data effect is shown.
- **Where:** `tools/packaging/install.sh:93-100`. `[ "$w" -ef "$cur" ]` is false when `$cur` does
  not exist. `runtime_state` (`:70-71`) then answers `none` because `$cur` is absent. So nothing
  refuses.
- **Reproduced:** on macOS, with a shell-script stand-in, ended by its own PID. The probe is

  installed path, the installed file is then moved away, and `a2`'s `install.sh` is run:
  - at `3943738d`: **exit 0**, "installed …", with the process still running;
  - at `b157352e`: exit 1, "a process started from $T/prefix/heimdall is running (pid …)".
- **`install.ps1`:** not affected. `Resolve-Final` is lexical plus link resolution, so it needs no
  file at `$cur`.
- **Fix:** match when `[ "$w" = "$cur" ]`, when `[ "$w" = "$curabs" ]`, or when
  `[ "$w" -ef "$cur" ]`. Here `curabs=$(cd "$(dirname "$cur")" && pwd -P)/heimdall`. Add a case
  to `install-selftest.sh` that moves the installed file away while the stand-in runs.

### `crates/stategen`, by reading against W1's review

- **R01:** `abandon` (`generations.rs:602-621`) now returns at once when `discard_staged` fails,
  keeping the intent and the temporaries. Every kept intent is settled by the next `open()`:
  - **An install or adoption with no pointer:** the intent is pending, or switching with the
    temporary pointer naming it. `pointer_was_never_written` is then true, and the staged
    generation is discarded.
  - **A restore or reset with a pointer:** the intent is unfinished and names another
    generation, so it is discarded and the intent removed.
  - **`publish` and `adopt`** call `open()` first, so a retry settles the leftover before it
    stages again.
  - **The name was free:** the discarded name was free when the intent was written
    (`require_free`), so it is never another operation's generation.
- **R02:** `has_generation` counts only entries that parse as a `GenerationName` and are
  directories. A lost pointer beside a real generation is still `PointerMissing`, as the new test
  asserts at its end.
- **R03 and the damaged-ledger refusal:**
  - `parse` treats one final all-zero record (plus any short tail) as torn, and every other
    undecodable record as `Damaged`.
  - `append` now parses first, so it refuses a damaged ledger before `truncate_sync` or
    `append_sync`. Nothing is written, as the test asserts byte-for-byte for three kinds of
    damage.
  - `trim` still refuses damage.
  - The restore fence reads the same entries, minus a torn zero record, whose append never
    returned.
- **The torn-tail line:** drawn correctly for the crash the crate models, one 48-byte append not
  yet synced. A final record with a valid prefix and a zero suffix is classed as damage. Since
  `282324ec` such a record stops every append until the attended path. That record could come
  from a write torn at a sector boundary with the size committed, in the power-loss class the
  crate does not claim. This is the conservative side, and U0-Q8 holds the repair question. It is
  noted here and not raised as a defect.
- **Revert proofs, by reasoning (not run):** each new test fails with its fix taken out.
  - R01: the old `abandon` removes the intent, so the next open is `PointerMissing`.
  - R02: `.DS_Store` alone makes the old check `PointerMissing`.
  - R03: `read` returns `Damaged(2)`, so `expect` panics.
  - Damaged ledger: the old `append` returns `Ok`.

Apart from R03, the report:

- counts a target's time only when its run line carries the current identity, or is an
