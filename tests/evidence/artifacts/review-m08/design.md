REVISE M08-D-R01 M08-D-R02 M08-D-R03

Review: bd6e0f40 against its sole parent de097dac; design review only. Severity follows ADR-0009 §2.1; implementation gaps below describe the proposed design, not executed failures of a nonexistent implementation.

Findings (most severe first)

M08-D-R01 — blocking — docs/decisions/0014-hardening-and-release-artifacts.md §3.6; docs/architecture/m08-plan.md U2b/Q1.
Ending grants and pausing policies does not end all recovered authority. A backup taken before client revocation restores an active management client; a later-revoked remote party can regain access when the runner resumes. ADR-0012 §§3.9–3.11 makes durable invitation/client state the admission authority. Define a restore quarantine for recovered clients, invitations, exposure/admission state and pending widening decisions, with explicit reauthorization and runner reconciliation before service resumes. Test backup → revoke/consume → restore → old-key/join/replay refusal. Preserve pins as identity information, not renewed authorization.

M08-D-R02 — blocking — ADR-0014 §§3.1–3.2/3.6/H3/H9; m08-plan U2b and §7.2.
The restore/reset protocol is unspecified at the two dangerous boundaries: selecting a backup from a different environment, and a crash/I/O failure while replacing the live SQLite family. “Restore's own transaction” does not establish that restored authority is disabled before its database becomes live. Specify backup/environment binding, exclusion of concurrent runtimes/issuers, staged validation and authority sanitization, atomic activation with WAL/journal handling, and preservation/recovery of the original family. Wrong-environment input must not silently replace identity; every interruption must recover an intact old state or a fully sanitized restored state. Add focused durable-boundary fault cases. Reset also needs an explicit inventory-unavailable refusal/disclosure when neither the old store nor a recovery inventory is readable.

M08-D-R03 — blocking — ADR-0014 §5.1; m08-plan U6a/§7.3.
An allow-list of fields is insufficient when an allowed field contains arbitrary text: the log tail and diagnostic findings remain open text channels. telemetry::redact_with_home (crates/runtime/src/telemetry.rs:295,447) deliberately preserves ordinary words, short strings and Heimdall IDs; it cannot guarantee removal of an unmarked short secret or identify every embedded identifier. Tagged-canary tests do not prove that promise. Restrict exported diagnostics to enumerated codes and typed safe values, or omit unsafe text; specify pseudonymization across every remaining string, keep the inverse map outside the bundle, and freeze the exact previewed bytes before confirmation/write. Identifier inclusion must never bypass secret/key/canary redaction. Test non-marker secrets, split/multiline key material and identifier-bearing diagnostics, without exporting planted values.

M08-D-R04 — moderate — prototypes/m08-probe/inventory.py; m08-plan §§1.1/9; ADR-0014 §§4.5/9.
cargo metadata resolves workspace/dev-enabled features; skipping dev edges afterwards does not undo feature activation. On the reviewed base, the retained macOS summary reproduces 234 third-party packages (224 normal + 10 build), but cargo tree -p heimdall --edges normal,build --target aarch64-apple-darwin --locked --offline selects 209: 25 metadata-only packages include borsh, defmt, palette and time. The script also labels normal-edge proc macros “linked”. Use a package/target/feature-selected graph with host/build distinctions; describe compilation separately from linker retention. Correct the counts and testkit-only list. A missing proptest string is not linkage evidence. Prefer a pinned SBOM tool plus a small validation adapter over a new resolver.

M08-D-R05 — moderate — m08-plan rule 2, U0, §3 trigger and W2.
“M07 freeze” is triggered by revision 7 becoming provisional. M07 U0 explicitly lands unused preparatory types; U3 subsequently changes live shapes/readers and U9 ratifies the contract. M08 U0 would meanwhile edit the shared CLI, schemas, contract and store. Gate shared edits on an explicit contract-owner handoff after relevant M07 emitters/readers land, or wait for ratification. The W0 new-file write sets are largely disjoint, but drafts, harness command tables and bundle input adapters are provisional and will need integration updates; do not call that contract independence.

M08-D-R06 — moderate — m08-plan §§4.1–4.2, §7.2, Q3; ADR-0014 §4.8.
Q3 recommends closing clean-machine rows with a fresh account plus static checking, while §4.2 and ADR-0014 correctly say that machine-wide runtimes remain. Static import checks cannot prove absence of all runtime/subprocess prerequisites. Keep the true Windows/macOS clean-machine rows blocked on B15; retain fresh-account runs as separate useful evidence. A limitation does not turn that fixture into spec A31's clean machine.

M08-D-R07 — moderate — ADR-0014 §§4.2/4.4; m08-plan U3a/§5.
The archive contains SHA256SUMS, which must hash every file inside it and the archive itself. That creates self-reference and an archive/manifest cycle; BUILD-RECORD's “each output's digest” needs the same exclusion rule. Define an inner payload manifest excluding itself and digest-bearing metadata, then an external checksum index over finalized archives/records. Verify against the repository-anchored external digest before installation, and make staged executable/helper replacement recoverable on partial I/O failure.

M08-D-R08 — moderate — m08-plan §§6.2–6.3/7.4; ADR-0014 §6.2.
Managed lane M can be debug-only and runner lane R can disappear, yet the A34 blocked-row list does not name missing release-managed/provider/route coverage. Mark those exact rows blocked or reuse expressly applicable release evidence; do not close them from mechanism runs. Invalidation must follow the executable and affected paths: remote, transport-iroh and WSL can be long-lived too, and root manifests/features/toolchain/build flags can change shipped behavior. Reassess the affected soak when those inputs change. The zero-login-after-revoke rule must name local admission versus already-issued offline credentials and their accepted residual windows, so it agrees with the existing revocation contract.

M08-D-R09 — moderate — ADR-0014 §4.2; m08-plan U7/§12, against plan §§10.2–10.4.
Explicitly package the final compatibility matrix and reference configuration, rather than merely relabeling a repository matrix and shipping schemas/payload examples. Assign the compatibility/deprecation policy and urgent-fix disclosure procedure. M09 appropriately owns the final go/no-go decision, but M08 alone does not deliver the owner's requested completed worksheet: hand off a concrete populated candidate worksheet with missing authorizations/rows, and name the M09 delivery step.

M08-D-R10 — low — tests/evidence/m08-probe-inventory-and-release-binary.json and artifacts/m08/probe/.
The evidence passes the schema but retains no command exit codes; the syft raw output is expressly absent, started_at is a date placeholder, and release-static-macos.txt is an inspection summary without exact counting commands/exits. Preserve actual invocations, exits and sanitized raw evidence for any retained claim. Until rerun, label the unavailable syft details and binary counts as recorded observations not independently reproducible proof; do not invent the missing values.

A Linux-arm64 container soak may establish that specific release workload on declared hardware, never native Windows/macOS custody or an unrun x86-64 72-hour result. Missing required rows stay blocked and the parent record obeys the lowest-row rule.

6. Economy: retain the existing property/adversarial cases and M07 replay corpus; add only new failure traces/assertions. Minimized fuzz cases can extend existing regression seeds rather than create duplicate tests. Do not automatically repeat unchanged 2–8 CPU-hour targets at every candidate or duplicate a native candidate run at an identical exit build; invalidate by affected boundary/build. Pinned cargo-deny and a conventional selected-graph SBOM/notices tool are sufficient; handwritten packaging verification can stay a small adapter. U6's separate pure crate is reasonable for ownership, provided it does not grow another diagnostics framework.
