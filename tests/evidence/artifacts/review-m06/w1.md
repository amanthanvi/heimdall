### Findings

**M06-W1-R01 — Blocking (ADR-0009 §2.1: remote trust & authority record corruption under concurrent owner/remote actions).** `crates/remote/src/invitations.rs:521-570, 614-657, 696-781`, `crates/remote/src/line.rs:507-520`
- **Problem:** `invite`, `join`, `revoke`, `expire_due`, and `reconcile` all call `sync_line` outside `store.transaction` with a stale `RemoteClientRecord` and no serialization against concurrent line writes or `revoke`. If `revoke` commits a `Revoked` tombstone, removes the `authorized_keys` line, and returns `Revoked { line_removed: true }` after `join`'s `reread` (`invitations.rs:650`) and before `join`'s `sync_line` (`651`), `join` writes a permanent (no `expiry-time`) `Active` line into `authorized_keys` and overwrites `remote_clients.line` back to `AppliedLine::Active` on the `Revoked` row (`reconcile` at `771-779` and `invite` at `563` have the same race, and `reconcile_line` has no file-edit serialization across callers). Separately, `invite`/`join` evaluate a pre-sampled `TimeReading` rather than sampling inside the committing transaction, and `join` does filesystem I/O (`lines.read_all()` at `620-623`) between that sample and commit.
- **Probe:** Temporary unit test (`HookLines` triggering `svc.revoke` inside `join`'s second `read_all()`) observed `revoke_line_removed=true`, `joined_line_written=true`, `db_state=Revoked`, `db_line=Active`, and 1 un-expiring active `authorized_keys` line remaining (exit 0). Existing tests run single-threaded sequentially and miss this.
- **Smallest fix:** Serialize `ManagementLines` reconciliation per runner with a lock/mutex that re-reads the authoritative client/invitation rows *inside* the sync step before calling `reconcile_line` and updates `AppliedLine` only if state still matches; sample `TimeReading` at commit time inside `store.transaction`.

**M06-W1-R02 — Blocking (ADR-0009 §2.1: false `Verified` remote-trust verdict & missed `authorized_keys` duplicate checks on normal host config).** `crates/remote/src/sshd_policy.rs:457-482`
- **Problem:** `verify_inner` splits `authorizedkeysfile` via `.split_ascii_whitespace()` (`line 462`). OpenSSH `sshd -T` strips quotes and prints unquoted space-separated entries, so a configured path containing spaces becomes indistinguishable from multiple paths. Each fragment passes `expand_keys_file` + `check_abs_path`, yielding `PolicyVerdict::Verified` with bogus `authorized_keys_files`, so `key_already_authorized` and `line_fingerprint` never inspect the real space-containing file while limited roles are admitted.
- **Probe:** Live macOS `/usr/sbin/sshd -T` (`OpenSSH_10.5p1`) on `AuthorizedKeysFile "/tmp/my keys/ak" .ssh/authorized_keys` printed `AuthorizedKeysFile /tmp/my keys/ak .ssh/authorized_keys` (exit 0). Passing that to `sshd_policy::verify` returned `Verified(VerifiedPolicy { ..., authorized_keys_files: ["/tmp/my", "/home/runner/keys/ak", "/home/runner/.ssh/authorized_keys"] })` (exit 0). Existing tests only use paths without spaces.
- **Smallest fix:** Parse the quoted `AuthorizedKeysFile` directive from the readable `sshd_config` / `-f` source alongside `sshd -T` (using existing OpenSSH tokenization), or fail closed to `owner_only` whenever multi-token `authorizedkeysfile` paths cannot be verified unambiguously against the config/disk.

**M06-W1-R03 — Nonblocking in W1 under ADR-0009 §2.1 (fails closed; blocks W2 pairing/M06-W0-R06).** `crates/remote/src/roles.rs:297-309, 477-488`, `crates/remote/src/invitations.rs:665-687`
- **Problem:** Contract rev 6.1 added `RemoteEnvironmentRequest::ActivationProbe { environment, nonce }` (`kind: remote_environment.activation_probe`), and `bridge::serve` (`crates/remote/src/bridge.rs:288-301`) forwards `ClientMessage::Request` directly. However, `roles::check` (`484`) only allows synthetic `SessionFrame::ActivationProbe`, so any real wire `SessionFrame::Request(Request::RemoteEnvironment(ActivationProbe { .. }))` hits `_ if record.state == ClientState::Pending` (`486`) and is refused `invitation_pending`. Moreover `roles::classify` (`297-309`) leaves `ActivationProbe` in `_ => class(P::Service, Unclassified)` (`NotAvailableRemotely` for active owners, `RoleInsufficient` for viewer/requester), and `Invitations::probe(&self, session)` neither checks `environment`/`nonce` nor `liveness` expiry.
- **Probe & test gap:** `pending_client_reaches_only_probe_and_join` (`roles.rs:632`) and `pending_key_reaches_only_probe_and_join` (`tests/model/remote_roles.rs:730`) only pass `SessionFrame::ActivationProbe`. A temporary probe deserializing the rev 6.1 golden JSON returned `pending=Refuse(InvitationPending)`, `active=Refuse(NotAvailableRemotely)`, `classify=RequestClass { permission: Service, effect: Unclassified }` (exit 0).
- **Smallest fix:** Match `RemoteEnvironmentRequest::ActivationProbe { .. }` in `roles::check` (`Verdict::Probe`) and `roles::classify` (`class(P::View, Read)`), validate `environment == self.environment` and non-expired invitation in `Invitations::probe`, and test the deserialized wire request.

**M06-W1-R04 — Nonblocking in W1 under ADR-0009 §2.1 (fails closed; blocks W2 U56 Iroh route establishment).** `crates/transport-iroh/src/dial.rs:13-15, 229-235`, `crates/transport-iroh/src/serve.rs:607-617`, `crates/app/src/routes_failover.rs:3-11, 194-226`
- **Problem:** `routes_failover::run_failover` holds `client_in` untouched until `establish()` reads the server's `SSH-…` identification line (`routes_failover.rs:194-226`). Meanwhile `transport-iroh` `serve::session` blocks on `conn.accept_bi().await` before calling `shared.target.connect()` (`serve.rs:607-617`), and as `dial.rs:13-15` notes, QUIC `open_bi()` opens the stream at the server only after the dialer writes its first byte. Thus every SSH route through U5a + U6a deadlocks until `identification_timeout` (note: against a stock Pigeons roost, stock `/pigeons/0` also waits for client bytes before connecting to `sshd`, requiring explicit U56 design handling if stock roost interop is kept).
- **Probe & test gap:** `e2e_tests.rs` only runs client-first `round_trip()`. Temporary probe with a loopback server writing `SSH-2.0-Probe\r\n` upon TCP accept timed out (`Err(Elapsed)`) with `target_accepted=0` (exit 0).
- **Smallest fix:** In `transport-iroh::serve::session`, connect to the loopback target once admitted (`register`) without blocking on `accept_bi()` first (or decide in U56 how client-first Pigeons streams satisfy server-first SSH failover).

**M06-W1-R05 — Nonblocking (`RouteHealthPayload` failure classification).** `crates/app/src/routes_failover.rs:337-340`
- **Problem:** Unlike `establish()` (`215-219`), when `dial()` returns `Err(DialFailure::Terminal)` (a leg's own host-key/auth failure before identification), `run_failover` breaks failover cleanly (`break`) but records `RouteFailureClass::Refused` instead of rev 6.1's `RouteFailureClass::AuthenticationOrTrust`. Existing tests only trigger `Terminal` via `LegEnd.terminal`, never `DialFailure::Terminal`.
- **Smallest fix:** Push `RouteFailureClass::AuthenticationOrTrust` at `routes_failover.rs:338` and add a `DialFailure::Terminal` assertion in `routes_failover::tests`.

**M06-W1-R06 — Nonblocking (W0-R03 test efficacy gap).** `tests/integration/paired_scope_m06.rs:365-373`, `crates/app/src/events.rs:788`
- **Problem:** `paired_scope_m06` exercises synchronous `AccessReady` `ensure`, leaving `open_operations()` and `unresolved_operations()` empty. Removing `&& visible_to(&op.key.caller, reader)` in `snapshot_data` (`events.rs:788`) still passes `integration_paired_scope_m06` (observed exit 0; 1 passed, 0 failed). `stop_m05::may_stop` (`stop_m05.rs:982`) and `delegate` (`operations.rs:10642`) also lack paired-owner negative integration cases (code guards are present).
- **Smallest fix:** Add an open/awaiting operation belonging to client B in `paired_scope_m06` and assert client A's snapshot omits it while B's and local owner's include it, plus a paired-owner `stop`/`delegate` denial check.
