FIX FIRST — M06-W0-R01 (audit scope), M06-W0-R02 (cutoff authority), M06-W0-R03 (paired-owner scope).

Reviewed a2576a51 against its parent ce5b0dc2. R02 and R03 block adopting the public contract readings under ADR-0009 §2.1. The corresponding remote handlers are unreachable in W0.

### Findings

**M06-W0-R01 — Blocking. The audit can pass a vulnerability in a supported Iroh build.** `tools/validation/check.sh:137–169`
- The gate filters by the host's standalone transport tree. On macOS it accepted a synthetic advisory for Windows `ipconfig 0.3.4`, which is newly locked and in the all-target Iroh tree. It also treats every package outside that tree as pre-existing even if an advisory is new or the package is linked by the eventual product binary.
- Audit the supported Iroh product build graphs across targets. Until the binary is wired, include the transport graph across supported targets. If a pre-existing advisory is accepted, record its exact ID under the owning decision.
- Test. Feed one Linux- or Windows-only advisory into the gate on macOS, a host-tree advisory, and an explicitly accepted baseline advisory.

**M06-W0-R02 — Blocking contract. Receipt time would replace the owner's cutoff time.** `crates/contract/src/remote.rs:270–277`, `docs/decisions/0006-public-contract-baseline.md:2387`
- A user schedules a cutoff for later today. A runner receiving it now has no instant to preserve and the draft tells it to end work immediately. ADR-0012 §4.5 and §7.2 retain cutoff semantics from ADR-0005 §6.1. The existing policy request carries `at` in `crates/contract/src/request.rs:995–1004`. This affects the owner's work after ordinary delivery or reconnection.
- Carry the effective cutoff instant in the decision-bound revision and preserve it on delivery. Specify how U4 persists and enforces the bound under uncertain time without allowing a replay to delay it.
- Test. Deliver a future cutoff early and late and replay it under uncertainty. Check the original bound, the reconciliation gate and expiry treatment.

**M06-W0-R03 — Blocking contract. Paired owners get an undocumented cross-client bypass.** `crates/app/src/events.rs:654–655`, `crates/domain/src/binding.rs:76–77`, `crates/app/src/operations.rs:10849–10852`, `docs/decisions/0006-public-contract-baseline.md:2420`
- Once wired, a paired owner could observe or cancel another client's operation using the role bypass. ADR-0012 §3.7 gives each client its own operations and permitted environment views. §7.2 and §8 explicitly allow either owner to deliver narrowing effects. Those permissions do not grant access to every caller-owned object.
- Preserve the local owner bypass. Scope paired ownership to principal plus client and grant cross-client powers only for the named actions. Make U1 apply visibility to event pages, resumed subscriptions and live events too. Those paths currently filter by event type and operation ID without checking the operation's caller (`operations.rs:10779`, `events.rs:575`, `crates/ipc/src/session.rs:847)).
- Test. Use two clients on one OS principal, including a paired owner. Exercise observe/cancel, binding ownership, snapshot, event pages and resumed/live subscriptions. Include the local owner and the specified cross-controller narrowing as positive controls.

**M06-W0-R04 — Nonblocking. The audit's database policy depends on ambient configuration.** `tools/validation/check.sh:129–148`
- With default cargo-audit 0.22.1 settings, a missing DB is cloned. Failed clone/fetch, an invalid DB or a fetched DB older than 90 days exits 1 without JSON and the wrapper fails. The tool reads project or Cargo-home `audit.toml`. A local `database.fetch = false` opens an existing DB without a freshness check. `database.stale = true` and advisory ignores also survive the current CLI flags. The explicit missing-tool skip returns success.
- Check in an authoritative project audit configuration with fetch enabled, stale disallowed and any accepted advisories named explicitly. Give DB failures a direct diagnostic when no valid report was emitted.
- Test. Start with an empty or stale fixture DB and an ambient config with fetch disabled. Use a fixture repository to cover successful fetch and denied fetch.

**M06-W0-R05 — Nonblocking in W0. The policy revision table can collide across controllers.** `crates/store/migrations/0009_remote.sql:89–99`
- The outbox and acknowledgement keys include producer, but revision rows use `(scope_key, revision)`. Two independent controllers can produce the same revision for the same scope. The second insert hit a uniqueness error in SQLite. U4 needs a defined resolution before either effect can be acknowledged as durable.
- Before adding a writer, persist both producer-scoped identities or specify a runner-owned revision allocator and durable mapping. Keep canonical policy reconciliation explicit so neither a pause nor a cutoff silently disappears.
- Test. U4's two-controller interleaving should use the same scope and numeric revision with different producers and verify both durable results and their replay.

**M06-W0-R06 — Nonblocking in W0. The pending join path has no matching capability for limited roles.** `crates/contract/src/ipc.rs:130–154`, `crates/contract/src/request.rs:1568–1569`, `crates/ipc/src/session.rs:929`
- A pending invite for a viewer or requester needs `join` under ADR-0012 §3.9. Both roles lack the capability required by `Join`. Opening that capability to all limited sessions would change the prescribed authority boundary.
- Define a pending-session negotiation/dispatch path limited to the activation probe and join. Keep the authenticated invitation and identity checks ahead of all recorded results.
- Test. Activate a viewer and a requester. Refuse adjacent management forms while pending and check an identity mismatch on retry.

**M06-W0-R07 — Nonblocking in W0. Invite has a fingerprint and no way to name the confirmed public key.** `crates/contract/src/remote.rs:148–157`
- ADR-0012 §3.5 and §3.9 require a pending line containing the receiving key. A runner cannot construct that line from the fingerprint. The packet defines no prior staged-key reference.
- Carry the public key or a reference to a previously verified key. Recompute the fingerprint and bind it to the exact key and role in the runner-local decision.
- Test. A mismatched key and fingerprint must produce neither a decision capable of enrollment nor an authorized line.

**M06-W0-R08 — Nonblocking in W0. The required request-ID set is not the set of widening actions.** `crates/contract/src/route.rs:161–191`, `crates/contract/src/remote.rs:130–157,224–228`, `docs/decisions/0006-public-contract-baseline.md:2379`
- A pure preference change among consented routes needs no new decision (ADR-0012 §2.1). Bootstrap owner enrollment widens (§3.3) and device retirement requires local attendance (§3.4, §3.10). Neither carries a request ID. Route add and transport enable depend on the actual consent delta. The existing grant/policy forms and future role, issuer-trust and time-source changes also need their specified replay semantics.
- Define replay per action. Retain or remove a preference ID as an independent idempotency choice. Explicitly separate local bootstrap and retirement confirmation from T-RA3's paired submission rule and name the terminal replay key for every widening request that a paired client can submit.
- Test. Reorder consented routes without a new decision. For each widening submission, replay the terminal result after local confirmation and verify one execution.

**M06-W0-R09 — Nonblocking. Declared shapes omit two U0 attachments.** `crates/contract/src/route.rs:142–152`, `crates/contract/src/request.rs:525–582`, `docs/architecture/m06-plan.md:78–85`
- U0 says to apply ADR-0012 §9 items 1–11. Item 9 adds routes and pins to the destination object and item 10 adds residuals to readiness. A client validating either new shape through the existing public schema cannot do so. The W0 deferral leaves old documents readable.
- Attach optional fields and regenerate schemas, or record an explicit plan decision assigning the attachments to U5a and U3/U4.
- Test. Validate the new fields through the containing schemas and retain the exact old serialization with the fields absent.

**M06-W0-R10 — Nonblocking. New event selectors already affect an existing request.** `crates/contract/src/event.rs:58–72,112–120`, `crates/ipc/src/session.rs:543–549,959–972`
- A local client can subscribe with `types: ["route"]` and get an accepted subscription that filters out old live events. None of the new events is produced. This is a read-filter effect outside the five fail-closed request families.
- Document that the new event types can be selected while their streams remain empty, or reject those selectors at the existing subscribe and observe boundaries until supported.
- Test. An IPC selector test should check the chosen behavior without constructing a remote event.

**M06-W0-R11 — Nonblocking in W0. The public compile fixture has Iroh's wildcard bind defaults.** `crates/transport-iroh/src/endpoint.rs:11–19`
- W0 never calls `bind`. The returned builder still has both default IP transports in Iroh 1.4.2. Reusing `closed_builder` and binding it in U6a would exceed ADR-0012 §2.1's minimal policy even with relays and the netdev probe disabled.
- Keep the compile fixture private or clear the default IP transports before configuring the explicit allowed binds.
- Test. U6a's bind test should verify the minimal policy has no wildcard addresses.

### ADR-0006 §18.2 readings

1. **Amend.** Keep unconditional W0 refusal. U1 must require a runner and a resolved bridge identity and role before accepting a client ID. A capability advertisement alone cannot establish that identity.
2. **Amend.** Obtain an explicit U0 deferral for attaching routes and pins, or attach them as ADR-0012 §9.9 requires. U5a owns behavior.
3. **Agree.** Existing store semantics are backed-up, forward-only and transactional. Rewrite “up and down” in the U0 plan as upgrade and fault rollback. A v8 reader refuses a v9 file after successful migration.
4. **Agree.** Report the role on paired negotiation while preserving the legacy local owner hello.
5. **Amend.** Keep the ordinary role intersection and define the pending join exception. Gate primitives and event delivery by permission and scope in U1.
6. **Agree.** The names preserve local environment management and keep route resolution transport-independent. General route add must enforce the same roost disclosure and consent if it can create an external-roost route.
7. **Amend.** Use R08's per-action mapping. Pure preference has no new decision, bootstrap widens, and retirement requires local attendance. Preserve terminal replay for paired widening submissions.
8. **Agree.** The producer is the authenticated client on the session. Caller-supplied effect IDs and targets do not establish identity.
9. **Amend.** Preserve the owner-authorized cutoff instant and its enforcement semantics, per R02.
10. **Agree.** Controller-initiated exchanges can carry the runner's challenge. The runner issues a fresh session-bound nonce and accepts only its designated owner's timely response, which can only shorten a bound.
11. **Agree.** Family plus subtype preserves the existing pattern. Keep the every-attempt audit obligation and treat failure-over as its subtype.
12. **Agree.** Store target generation once in the typed target. Keep all four effective key parts and define policy revision identity across producers before U4 writes.
13. **Agree.** Destination and account identify the runner path. `realization` was already required in revision 5.
14. **Amend.** Attach optional residuals to readiness now or record a plan deferral. Rust literal updates do not require a change to old wire bytes.
15. **Agree for W0.** Uniform in-process refusal is effect-free. U1 needs the pre-dispatch pending, revocation, attendance and role rules before any handler can create a record or disclose a result.
16. **Amend.** Reuse decisions and the four-part effect keys. A separate generation is compatible if every admission-authority change advances it atomically. Define scoped key uniqueness and policy revision reconciliation before writes. Keep the all-discarded classification limited to empty W0 tables and require recovery/purge cases before writers, including transport writers.
17. **Amend.** Preserve global local-owner access. Paired callers use client-scoped ownership plus explicit role-permitted environment views and named narrowing powers. Cover all event delivery paths.
18. **Agree.** The new prefixes, OpenSSH SHA-256 fingerprint form and lowercase 64-hex Iroh ID are consistent with the declarations and G06 format.
