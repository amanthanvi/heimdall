## 2. Wave 2 Findings (`M06-W2-R01..R06`)

### `M06-W2-R01` [Blocking — ADR-0009 §2.1: lasting remote-trust transition triggered by remote `join` across wall clock step / I/O]
- **Where:** `crates/remote/src/invitations.rs:466-489, 573, 647, 715-754`; `crates/runtime/src/paired.rs:512-520, 560-577`.
- **Problem & Probe:** `at_commit(sample: &TimeReading, now: &TimeAnchor)` advances `sample.checked_wall` solely by `now.continuous - sample.boot.continuous` and never reads `now.wall`. In `Invitations::join`, `self.lines.read_all()` runs before the SQLite transaction commits, and `sync_line` re-invokes `at_commit` on the request-entry `sample`. Temporary probe `review_probe_at_commit_wall_step_and_rollback` (`cargo test --locked -p heimdall-remote --test model_remote_roles`, `EXIT=0`) proved two failures against unmodified code: (1) jumping `now.wall` +20 min past the 15-min `expires_wall` while `continuous` advanced +1s during `read_all()` still activated the client (`ClientState::Active`, stripping `expiry-time` from `authorized_keys`); (2) rolling `now.wall` back -2 hours during `read_all()` bypassed `TimeGate` and still activated instead of returning `Refusal::TimeUncertain`.
- **Smallest fix:** Compare `now.wall` in `at_commit`: advance `checked_wall` to `projected.max(now.wall)` so forward wall jumps past `expires_wall` expire immediately, return `TimeReading::uncertain` if `now.wall` steps backward past step tolerance relative to `projected`, and re-check `time_reading()` / `TimeGate` after `read_all()`.
- **Test gap:** Existing tests move `wall` and `continuous` together or roll wall back before `TimeGate`; none step `now.wall` independently across the `read_all()` -> commit window.

### `M06-W2-R02` [Nonblocking — ADR-0009 §2.1: fails closed, no unconsented trust]
- **Where:** `crates/heimdall/src/m06_cmd.rs:1438, 1489, 1519, 1547-1552`; `crates/app/src/remote_env.rs:728-736`; `crates/runtime/src/service.rs:888-898`; `crates/runtime/src/paired.rs:130`.
- **Problem & Probe:** `remote_init` still records `AppliedLine::Absent` and returns `"line_written": false` (`"No management-line writer exists in this build"`), even though wave 2 implemented `runtime::paired_lines::AuthorizedKeysFiles`. Probe running `./target/debug/heimdall --home ... --json remote init` in a scratch home (`EXIT=0`) left `.ssh/authorized_keys` absent (`authorized_keys_exists=False`). Consequently, `RemoteEnvController::add` (`remote_env.rs:728-736`) fails its immediate `sessions.open(SessionTarget { name: SessionName::Bootstrap(...), ... })` unless `service run --runner` starts separately afterward (and `remote_init` grabs `InstanceLock` via `writer(&paths)`, blocking if a runner daemon already runs). In addition, `service.rs:891` hardcodes `AuthorizedKeysFiles::sshd_default(dir)` and `paired.rs:130` keeps `RunnerOptions::management_policy = ManagementPolicy::OwnerOnly`; `sshd_policy::check_effective_policy` has zero production callers in `crates/`, preventing custom `AuthorizedKeysFile` reconciliation and limited roles from CLI `service run --runner`.
- **Smallest fix:** Wire `AuthorizedKeysFiles` (from `sshd_policy::check_effective_policy` when verified, else `sshd_default`) into both `remote_init` and `service run --runner` (`RunnerOptions::management_policy`).
- **Test gap:** `e2e_environment_runner_m06` manually starts `service run --runner` between `remote init` and the K_mgmt connection; no test exercises `check_effective_policy` in `service_cmd.rs`.

### `M06-W2-R03` [Nonblocking — same-user file hygiene]
- **Where:** `crates/runtime/src/paired_lines.rs:289-307, 374-384`.
- **Problem & Probe:** Unlike `put` and `remove`, which read `authorized_keys` via `unix::read_nofollow` (`O_NOFOLLOW | O_CLOEXEC`, `meta.is_file()`), `read_all` (`293`) and `others_unmarked` (`376`) use plain `std::fs::read(path)`, following symlinks without a regular-file check or byte limit (and blocking if pointed at a FIFO/device). Confirmed via temporary probe `review_probe_read_all_and_others_unmarked_follow_symlink` (`EXIT=0`).
- **Smallest fix:** Replace `std::fs::read` in `read_all` and `others_unmarked` with a bounded `read_nofollow`.
- **Test gap:** Existing `paired_lines` tests check symlink refusal only on `put`/`remove` of `authorized_keys`.

### `M06-W2-R04` [Nonblocking — Windows DPAPI path-following inconsistency]
- **Where:** `crates/credential/src/mgmt/windows.rs:104-116, 166-184`; `crates/credential/src/iroh_windows.rs:108-120, 179-190`.
- **Problem:** Both stores check `symlink_metadata` before `put` and create `.dpapi` blobs via `sys::create_owner_only_new`, whereas `ensure_dir()` (`self.dir.is_dir()`) and `load()` (`std::fs::File::open`) do not reject directory/file reparse points (mitigated by user-private ACLs, `BLOB_MAX_BYTES + 1` cap, and DPAPI `unprotect` entropy binding). Observed by inspection; Windows native run out of scope here.
- **Smallest fix:** Verify `symlink_metadata` / owner ACL in `ensure_dir` and open blobs with `FILE_FLAG_OPEN_REPARSE_POINT` in `load`.

### `M06-W2-R05` [Nonblocking — pre-existing M05 unbounded test wait on macOS long `TMPDIR`]
- **Where:** `crates/runtime/src/managed_store/live_tests/` (pre-existing M05 tests).
- **Problem:** Running unfiltered `cargo test --locked -p heimdall-runtime --features iroh --lib` under a long macOS scratch `TMPDIR` pushed Unix socket paths past the 104-byte `SUN_LEN` limit, causing M05 tests (`follower_scope::decision_joined_follower_refused_when_evidence_changes_after_leader_commit`, `pipeline::decision_joined_follower_gets_its_own_materialized_binding_and_both_sign`, `pipeline::crash_between_materialize_and_confirmation_leaves_no_endpoint_file_or_key`) to hang at 0% CPU until stopped (`task-331`). (`heimdall-credential`'s `certificate_identity_file_selection_observed_per_client` also panicked on `SUN_LEN` with long `TMPDIR` and passed 17/17 under `TMPDIR=/tmp`.)
- **Smallest fix:** Bound `live_tests` waits with explicit timeouts and fail fast when socket path construction fails.

### `M06-W2-R06` [Nonblocking — ADR-0012 §5.5 item 5 pre-dial on first Iroh route]
- **Where:** `crates/app/src/routes_failover.rs:466-505`.
- **Problem:** When `routes[0]` is `LegPlan::Iroh`, `run_failover` calls `dialer.dial(route, config.connect_timeout)` before reading/validating the client's identification line (`held.identification`), initiating one outbound QUIC dial before rejecting invalid/silent client bytes with `IdentificationTimeout` (zero client bytes are forwarded, and `routes[1..]` skip dialing via `held.cannot_identify()`).
- **Smallest fix:** Read and validate `held.identification` prior to `dialer.dial` when `client_first` is true.
