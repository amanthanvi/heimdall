## New findings

### M07-W1-R01 — Blocking. A resize can bypass the current-frame consent guard for a durable action.

`crates/heimdall/src/tui/mod.rs:303`, `:334–359`, `tui/worker.rs:174–198`, `tui/model.rs:639–655`.
On Unix the worker forwards resize asynchronously. When terminal input wakes the main loop, it submits the keys against the prior frame before draining that resize or repainting. The frame counter tracks rendering, so it still considers the previous, wider confirmation current.
In a macOS PTY I drew the complete stop confirmation at 120×40, briefly suspended only the test process to queue the geometry change and input in order, shrank to 40×5, queued `yes` and Enter, and resumed. The offline TUI submitted 24/24 attempts. Against an isolated runtime the stop completed and a later ensure for that fixture work ID returned exit 4, `CREDENTIAL_EXPIRED/work_stopped`. The preceding wide frame had shown the action. At Enter the terminal was too small, and the valid frame had not been redrawn. This is an ordinary resize/input ordering, and it can permanently stop a work ID.
Smallest fix is to invalidate guarded confirmation when the terminal's current geometry differs from its last rendered geometry at submission, reject that Enter, and repaint. Route both Settings and stop through the same check. The existing tests resize by rendering a new frame first. Add a PTY regression that queues the resize and Enter before the redraw and checks the runtime has no stop record. Settings shares the event-loop exposure. The live mutation probe exercised stop.

### M07-W1-R02 — Moderate. Human status overstates both desktop-lock behavior and configured access.

`crates/heimdall/src/output.rs:287–303`, `:374–395`, `crates/app/src/lock.rs:298–325`, `:406–410`.
The CLI turns the aggregate personal setting into a categorical outcome. On a live scratch runtime, `inspect capabilities` returned `continue` and explicitly said continuity was unverified. The CLI said work continues while the desktop is locked. One personal revoke policy can make the aggregate revoke even when other work has different terms, and workspace policies are excluded from that aggregate.
The same summary prints any unpaused environment-matching policy as “uses … automatically,” including a workspace-only policy in a different or inactive project. Overview has the same context problem and says a long, fresh line is stale at 40 columns (`tui/m07.rs:618–658`).
Use a saved-setting label and the runtime disclosure, identify workspace scope for configured access, and use a length-appropriate summary in the TUI. Add qualified/unverified, mixed-policy, workspace-only and long fresh-list fixtures. The current tests accept the coarse summary. This is a user-facing claim, with no state mutation in the status path.

### M07-W1-R03 — Moderate. The enrollment wait notice misstates what Ctrl-C does.

`crates/heimdall/src/enroll_cmd.rs:265–271`, `output.rs:468–475`, `enroll_cmd/drive.rs:260–267`, `:380–392`.
The notice wraps the entire client-executed enrollment loop and says Ctrl-C stops waiting without canceling the request. During a remote step, Ctrl-C aborts the local SSH process group, sends no step result and returns `OUTCOME_UNKNOWN` with reconciliation required. That differs from a server-side operation wait.
Use an enrollment-specific notice that says the step is interrupted and its outcome may need reconciliation, or explain only pure server waits with the generic text. A slow fixture enrollment with a controlled interrupt catches it. The `operation wait` and initial ensure tests exercise correct wording for their own paths.

### M07-W1-R04 — Moderate. PowerShell launch errors affect the prompt, and failed children can supply accepted state.

`crates/heimdall/src/activate_cmd.rs:739–761`, `:764–796`, `tests/e2e/m07_powershell_hook.rs:329–349`.
