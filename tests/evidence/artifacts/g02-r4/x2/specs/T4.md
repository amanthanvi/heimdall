### `profile show` and `tui` reject my profile when the path is a symlink

I keep my profiles in a dotfiles repository and link them into place (GNU stow style). The path I
pass to `--file` is therefore a symbolic link to an ordinary TOML file. heimdall-proto refuses it,
and the file it points to works fine.

**Steps to reproduce** (any valid profile will do; this uses the repository's
`tests/fixtures/g02/profiles/homelab.toml`):

```sh
mkdir -p /tmp/repro/dotfiles /tmp/repro/config
cp tests/fixtures/g02/profiles/homelab.toml /tmp/repro/dotfiles/homelab.toml
ln -s /tmp/repro/dotfiles/homelab.toml /tmp/repro/config/profile.toml

heimdall-proto profile show --file /tmp/repro/dotfiles/homelab.toml --json   # works: exit 0, PROFILE_OK
heimdall-proto profile show --file /tmp/repro/config/profile.toml --json     # fails
```

**Actual:** the second command exits 2 and prints

```
{"schema_version":"1","state":"failed","code":"USAGE_ERROR","data":{"error":{"key_path":null,"message":"profile path is not a regular file"}},"warnings":[],"next":null}
```

`heimdall-proto tui --file /tmp/repro/config/profile.toml` exits 2 straight away with the same
complaint. A relative link (`ln -s ../dotfiles/homelab.toml profile.toml`) fails the same way.

**Expected:** a link that points to a regular profile file works exactly like the file itself, in
both `profile show` and `tui`.

**Version:** heimdall-proto 0.0.0-g02, on macOS (darwin-arm64) and on Linux (linux-arm64).
