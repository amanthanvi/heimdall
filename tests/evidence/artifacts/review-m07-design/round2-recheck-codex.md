### New choices

- **`pages/1` and whole-or-refuse:** Sound at the handshake and legacy-response boundary. Freeze the paged result only after defining stubs, role coverage, and the `page`/`select` grammar (RC03, RC05).
- **Partial snapshot and rebuild:** An honest partial snapshot is sound. The proposed live re-read algorithm cannot yet establish either a complete cache or a durable resume point (RC01).
- **`Subscribed.backlog` and checkpoints:** Sound if it counts exactly the visible, filtered backlog frames and the receiver explicitly resets on any gap. A partial snapshot alone cannot advance the durable state checkpoint (RC01–RC02).
- **Oversized event resync and list stub:** Resync is a reasonable state-recovery signal with an explicit history gap. A cursor hint cannot substitute for the snapshot. A stub is usable for enumeration only if the caller can distinguish omitted content and resolve its identity safely (RC02–RC04).
- **`route_undetermined`:** Sound for a required dependency that cannot be established. Keep M06's per-candidate rules and its same-grant check in the helper (RC04).
- **Write-time nested caps:** Sound for user-authored inputs with specified limits and upgrade behavior. Unsafe as a ceiling on required pending narrowing, and insufficient on their own to bound reads (RC06).
- **H2 tool loop:** Deterministic tool selection is a distinct harness style. The last envelope alone cannot drive the workflow, and H2 calling the reference wrapper exercises that same consumer (RC10).

### Findings

- **M07-RC-R01 — G08 blocker.** ADR §§5.2, 5.5–5.6; M06 `app/events.rs:706–816`, `app/operations.rs:9694–9709,9747–9774,10752–10806`. A filtered live stream can omit the settlement of an operation included in the snapshot. Today a visibility read can also suppress an event for a vanished row, and the snapshot includes managed-environment operations while backlog reads an environment log. An older page can overwrite a newer point read, and standalone `observe events` has no live stream to keep. The rebuild also leaves the authority generation and role-scoping rules for pending decisions undefined. **Fix:** define a scoped rebuild baseline with full section membership, order list application before newer updates, and cover removals, generations, filter changes and unavailable reads explicitly. Give the observe-only path a transition onto that baseline. On an unhandled gap restart the rebuild, and commit cursor and rebuilt state together only after verified completion. Alternatively serve bounded continuation from a stable server-side baseline. Test filtered, paired and disconnected rebuilds.
- **M07-RC-R02 — G08 blocker.** ADR §§4, 5.3–5.6; M06 `ipc/session.rs:859–915,1080–1112`; `heimdall/cli.rs:2424–2450,2473–2495`. A kept stream can emit later cursors after dropping events, and the text gives no rule to suspend checkpointing or replace that stream before resuming. The count must exclude hidden/filtered rows and control markers; oversize replacement already happens in backlog as well as live delivery. PC5 exposes a head cursor without its snapshot and conflates the page budget with the frame limit. §5.2 promises a terminal `client.revoked` event, while §4 assigns exit 6 to a terminal `resync_required` event for that same case. **Fix:** freeze the checkpoint on a gap, replace/unsubscribe the old stream and resume from the last applied cursor using the same filter. Specify exactly which frames count and test disconnect at the head, early termination, and a gap followed by a later event. For pages, allow a fitting singleton or document the distinct cutoff and explicit history loss. Require a fresh applied snapshot before using its new cursor. Publish one revocation termination and allow an error-only first line when subscribe fails.
- **M07-RC-R03 — G08 blocker.** ADR §§1.3, 3.2, 6.1, 6.4; M07 U6. The last page can say `complete: true` while containing a stub. Traversal ending and content completeness are distinct, so a TUI or an aggregate consumer can falsely publish complete data. Empty terminal pages also contradict the unconditional one-item rule. **Fix:** separate `more`/token from completeness or use a typed omission status that survives aggregation, define an empty terminal page, and test a final-page stub and the TUI's stale/unavailable state. Whole reads must return complete content or the typed refusal.
- **M07-RC-R04 — Wave and G08 blocker.** ADR §6.3 and D21; M07 U3; `connect_cmd.rs:223–240,295–306,639–671`; ADR-0012 §5.4. U3 permits a page traversal even for internal resolution, and an ID-only stub has no alias or hop metadata. A lookup failure or an incomplete record must never select the existing no-route or projection fallback. **Fix:** use point or dedicated complete lookups for internal resolution, with traversal for enumeration. Treat absent, omitted, malformed and unavailable required facts as undetermined, preserve M06's same-grant check on each selected or attempted jump, and add a stub/failed-lookup case beside the deleted-hop test.
- **M07-RC-R05 — G08 blocker.** ADR §§5.5, 6.1–6.3, 9; M06 `contract/ipc.rs:129–154` and ADR-0006 §18.5 rulings 5, 17. Snapshot rebuild depends on `pages/1`, and the index promises paging to all read roles. M06 uses explicit requester/viewer capability sets, but D2 changes neither or specifies a permitted fallback. The opaque token contract does not say how binding fields are validated against tampering. `page` plus `select` has two competing result shapes. **Fix:** specify read-role negotiation with unchanged subject authorization, validate the token's entire scoped tuple and position with an integrity check, and reject or define combined forms, including limits and an empty selector. Test limited roles, changed sort/scope and tampered tokens.
- **M07-RC-R06 — Wave and G08 blocker.** ADR §6.4 and D20; M07 U3; M06 `contract/remote.rs:436–459`, ADR-0012 §§7.2, 7.4; `app/catalog.rs:979–1004` and `app/operations/portable_m05.rs:466–471`. A count cap neither proves a byte limit for variable strings and attached decision scope nor bounds fetching oversized legacy documents. A cap on `remote_pending` must never refuse, drop or falsely acknowledge a required narrowing effect. U3 says M06 keeps the environments arm but assigns no owner to its paged/select contract. **Fix:** cap/project the view only for pending effects and keep durable effects intact and discoverable. Specify subject byte and count bounds, exact authoring validation at all write ingress including import, and a readable legacy path. Bound store reads before materializing over-limit rows, including whole-or-refuse and event backlog paths. Assign the environments integration and test legacy and maximal records.
- **M07-RC-R07 — Wave and G08 blocker.** ADR §4, D19/PC4; M06 `ipc/session.rs:473–477,820–826,1127ff.` The generic fallback is after dispatch and today's response helper sets `effect_status: none`. A code-only substitution can report no effect after work committed or became uncertain, and `narrow_request` could prompt a different intent. **Fix:** keep the ruled `USAGE_ERROR/response_too_large`, preflight where possible, and for post-dispatch overflow preserve truthful effect status and bounded recovery/operation references. Test a settled or uncertain mutation reply as well as a listing.
- **M07-RC-R08 — G08 blocker.** ADR §7/D16; M06 `remote/widening.rs:253–303,358–408` and ADR-0006 §18.5 ruling 7. W1 replays an expired pending same-key record as `DECISION_STALE`, and an approved record without a result as `OUTCOME_UNKNOWN`. Rev 2 promises fresh decision replacement and a retention window but does not define that replacement transaction or the crash-claimed record's recovery lifetime. **Fix:** resolve expired vs terminal behavior with M06, preserve conflict and durable uncertainty without re-execution/expiry while unresolved, and require restart replay coverage for pending, claimed, terminal and expired records before D16 is ratified.
- **M07-RC-R09 — G08 blocker.** ADR §§1.3, 11–12; M07 U0, U3, U5b, U6 and §3. U0 promises atomic migration but W1 submits provisional types/schema changes while W2 changes emitters and W3 changes frontend readers. PC5 omits the event-page emitter and the pre-existing valid-event cap distinction; PC6 omits the live publisher/session and CLI stream reader. The corpus from one current writer does not by itself cover historical shapes. **Fix:** land each changed live wire shape together with its emitters, all in-tree readers and goldens. Keep W1 preparatory where necessary. Include real prior-version row variants or migrated fixture stores in the replay suite, and inventory CLI, TUI and installed artifacts with the affected corrections.
- **M07-RC-R10 — G08 blocker.** M07 §§4, 5a, 6; ADR §1.2; plan §§3 G08, 5 M07; spec A32. H2 cannot choose its first call from a last answer, and multiple successful operations share `OK`/null next with different subsequent goals. Its wrapper dependency cannot also prove an independently implemented wire consumer. The skew hello rejection does not exercise an operation that negotiates successfully and then lacks a required capability. §6 requires native A32 verified while listing foreign-owner rows blocked, and the parent milestone still requires A30 pass despite the explicit exception. **Fix:** give H2 a task goal, typed state and defined inputs, prove distinct composition independently of wrapper behavior, and add a native operation-level refusal fixture. Reconcile the controlling exit mapping with the A30 ruling and state precisely which blocked rows prevent ratification; keep Rev 7 provisional until the required native A19/A32 rows actually pass.
- **M07-RC-R11 — Nonblocking design correction.** ADR §8 and D12; M07 §4; `heimdall/service_cmd.rs:364–407`. Specify the expected environment as an input with the old explicit endpoint, and source or validate all advertised instance fields, including existing PID/version, against the verified connection. Extend the restart fixture beyond the new endpoint field and align the Unix permission predicates with the adopted baseline.

### D19–D21 and PC1–PC8

- **D19 / PC4:** The ruled code, reason and exit 2 are correct. Preserve effect semantics and migrate generated typed error schemas plus CLI/wrapper consumers (RC07, RC09). No stored row rewrite is implied.
- **D20:** Incomplete. Cap policy, compatibility/refusal reason, owning writers, durable pending-effect behavior and legacy reads need RC06. List the new validation explicitly as a pre-release change with migration/read-compatibility coverage.
- **D21:** Token refusal and fail-closed intent are correct. Publish the route reason/code pair in discovery and test it through the CLI and route/helper boundary. Token binding and internal callers need RC04–RC05. Neither change calls for a persisted-row rewrite.
- **PC1:** `boundary_seq` has no published/CLI reader in the reviewed baseline. Removal is compatible with the ruling; snapshot shape/consumers and recovery need RC01 and RC09.
- **PC2:** Typing with existing keys is sound. Preserve subject metadata such as operations' counts and projections' record in the legacy form; inventory emitters and migrate readers together (RC09).
- **PC3:** Sound with the field inventory and nullable legacy fixtures. The persisted forms retain their documented nulls. Verify old read-envelope values and goldens in the same change.
- **PC5:** Use `RESYNC_REQUIRED/event_too_large` for a genuinely undeliverable stream item with a documented gap/recovery path. Clarify the one-frame refusal rule and migrate page and stream consumers (RC02, RC09).
- **PC6:** `history_trimmed` is a valid distinction. Migrate production stream control/consumers with the wire expectations and preserve old stored event payloads (RC02, RC09).
- **PC7:** Authorized and replay-neutral as a CLI rename. M06 applies it with registration, help and any rendered callers of renamed commands. Keep the hidden helper entry point as ruled.
- **PC8:** Authorized behavioral change. Keep the in-transaction guard, scoped existing work references and bounded error data. Historical recorded outcomes replay as written.
