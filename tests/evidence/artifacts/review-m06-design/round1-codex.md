FIX FIRST

Blocking findings

- **M06-D-R01** — The runner does not yet define a fail-closed boundary between a restricted SSH client and its local owner socket.
- **M06-D-R02** — Remote owner approval can bypass the accepted attended decision contract.
- **M06-D-R03** — Invitation activation lacks a durable one-use transition and authenticated delivery of the initial host pin.
- **M06-D-R04** — The route design can bypass SSH pinning or the existing bastion authority checks.
- **M06-D-R05** — The Iroh policy leaves ways to use infrastructure or keep admission beyond the recorded consent.
- **M06-D-R06** — Revocations and issuer state can diverge across two controllers.
- **M06-D-R07** — The proposed Unix endpoint key store needs a custody decision that meets the spec.

Reviewed the uncommitted design and artifacts in place at base **144fa477**. G06 supports choosing embedded Iroh and one-way Pigeons interoperability for implementation. G07 supports choosing OpenSSH for management and the memory-only credential model for the runner. Both gates still lack required acceptance evidence. Evidence gaps below are nonblocking under the narrow merge test in ADR-0009 §2.1 unless they accompany a trust, data, recovery or consent failure. The gate and release criteria in plan.md still apply.

## Findings

### M06-D-R01 — Enforce the restricted management session end to end

- **Blocking under ADR-0009 §2.1.** A paired remote party could obtain the runner account's authority or another client's data.
- **Where.** ADR-0012 §3 items 4–6 and §9 item 3. ADR-0006 §§2.1, 2.3, 7.1 and 8. G07 §§2.2, 8 and R3–R5.
- **Problem.** The fixture proves OpenSSH's per-key controls on its own configuration. An adopted sshd may apply a different authentication source or an account-level forced command, or accept client-controlled environment settings that affect the login shell before the bridge runs. Checking argv inside the bridge cannot repair those cases. A textual key search in one file also cannot establish which authorization source won. At the next boundary, all bridge processes have the runner's UID. If a remote hello reaches the owner socket unmediated, the runtime can see only that UID and accept a caller-supplied identity. Two requesters also share the legacy UID/role idempotency namespace, so a colliding request ID can return another client's operation.
- **Smallest fix.** Document and enforce the effective sshd/account prerequisites before activating management, including auth sources, command precedence, environment and safe command/path rendering. Fail closed on unsupported configurations and confirm the enrolled key reaches the expected restricted bridge before reporting activation. The bridge must originate the sole local hello, install the client ID from fixed arguments, reject client identity assertions, and keep the remote session bound to that ID. Include client ID in caller context, idempotency, operation ownership and cursors. Recheck revocation for requests and existing subscriptions. Keep the documented same-account owner equivalence.

### M06-D-R02 — Preserve explicit consent when adding remote owner control

- **Blocking under ADR-0009 §2.1.** A paired remote process could authorize a durable grant or trust change without an explicit owner decision.
- **Where.** ADR-0012 §§3.6, 4.2, 4.4, 6.1, 8 and 9. ADR-0006 §§2.3, 3.1 and 13.3 item 2. ADR-0005 §3.6.
- **Problem.** ADR-0012 requires attended remote approval, calls hello unchanged and marks the contract deltas additive. ADR-0006 makes paired sessions unattended pending an explicit G07 ruling with threat-model rows. Treating the owner role or a client-supplied attendance flag as approval would let unattended automation enroll an owner, add issuer trust or widen scope. The nonce-bound automatic time sample also needs a clear boundary from the existing manual time override.
- **Smallest fix.** Keep paired sessions unattended until a named revision specifies controller-side attendance with threat-model rows. Reuse a server-issued decision bound to the authenticated owner, environment, action and revision, with explicit confirmation and fail-closed replay handling. Apply it to authority-widening actions. Specify separately that an authorized time sample cannot perform manual time confirmation or reset a deadline.

### M06-D-R03 — Bind and durably consume one invitation

- **Blocking under ADR-0009 §2.1.** A remote party could substitute the environment being enrolled, or a crash could leave stale authorization or strand an enrollment.
- **Where.** ADR-0012 §3 items 2, 4, 7–8. G07 §2.2. M06 plan U1–U2. Spec §8.6.
- **Problem.** The invitation's public key binding is sound if the owner verifies the receiving key and the receiver authenticates the initial bundle. The proposal specifies neither handoff check. Substitution can pin an impostor environment on the receiver or enroll a different key under the chosen role. The design also equates an authenticated hello with consumption, then promises both that consumed records refuse and that the same key remains usable. The database and authorized-keys write can disagree after a crash. An SSH session authenticated before expiry can defer its hello beyond expiry because sshd checks time at authentication.
- **Smallest fix.** Use an authenticated exchange or explicit fingerprint confirmation for both pins. Require a distinct join operation over the forced command and a runner-side compare-and-set that verifies the invitation ID, receiving identity, role, deadline and live generation. Persist activation or revocation before changing the line, and reconcile the exact line idempotently on retry. A lost reply may recover that result. A later ordinary connection authenticates as an active client without consuming anything. Expired or revoked enrollment stays refused even when a line rewrite fails. Cover delayed hello and interruption between the database and file writes with one focused fault test.

### M06-D-R04 — Keep SSH host trust and bastion authority on every route

- **Blocking under ADR-0009 §2.1.** An inherited SSH setting or an unauthorized bastion dependency can invalidate the host pin or grant out-of-scope remote access.
- **Where.** ADR-0012 §§3.1, 5.1–5.5 and 7.4. ADR-0010 §5 and §9 items 3–4. M06 plan U2/U5 and A25/A26. Spec §§9.1 and 14.2.
- **Problem.** A host-key alias and private known-hosts file alone do not exclude inherited trust providers, a configured control path or a permissive checking mode. OpenSSH can attach to an existing master even with ControlMaster disabled when a matching ControlPath remains configured. The multi-route helper also omits the conditions for authenticating the bastion with its own approved dependency. Treating the jump as a generic stream could let a destination use a managed jump outside the grant.
- **Smallest fix.** Use an isolated management config and enforce strict catalog pins at both hops, with alternate trust sources and management multiplex reuse disabled. For projected ordinary clients, verify the effective settings and refuse combinations that defeat the pins. Keep single-hop native ProxyJump, including the existing scope, forwarding and readiness checks, inside the multi-route helper. Explicitly amend ADR-0010 §5(b) to permit only Heimdall's fixed helper for multi-route or Iroh cases, with typed inputs and approved route lookup. Extend the existing two-hop substitution test.

### M06-D-R05 — Enforce exposure policy at every endpoint and route

- **Blocking under ADR-0009 §2.1.** A remote route update or ordinary disable/revoke could produce third-party contact or access to sshd beyond recorded consent.
- **Where.** ADR-0012 §§1.2 and 2.1–2.6, §3.8. G06 §§3–5. M06 plan U6. Spec §§9.2 and 14.2.
- **Problem.** Minimal, disabled relays, cleared discovery and no portmapper are good defaults. The approved profile must also constrain explicit peer relay hints, addresses learned through lookup, direct UDP and ancillary DNS/net reporting. The probe takes its peer relay hint separately from the endpoint relay map. The n0 capture used the stock portmapper-enabled fixture, so it cannot prove a future profile's exact traffic. A named bind address can still be a wildcard or a non-loopback interface. The ADR also gives client revocation no defined effect on a live serving allowlist. A revoked paired endpoint could retain network access to sshd after losing management rights. Stock roost compatibility adds a separate exposure and discovery choice on the server side.
- **Smallest fix.** Give dialer and server explicit effective exposure policies. Build all addresses and relay hints from those policies, and fail closed on unapproved hints or inability to apply the policy. Require separate consent for non-loopback listeners, wildcard binds, direct fallback and public infrastructure. Enforce the loopback SSH target and a nonempty endpoint-key allowlist before forwarding. Bind allowlist changes to authenticated enrollment, rotation and revocation, including existing Iroh streams where revocation promises their closure. Disclose authenticated peer access as reachability only. Treat stock roost as an explicitly adopted external server with its own broader exposure.

### M06-D-R06 — Make time, issuance and revocation converge across controllers

- **Blocking under ADR-0009 §2.1.** An ordinary competing controller, dropped acknowledgement or stale issuance can preserve remote authority after it has been reported revoked.
- **Where.** ADR-0012 §§4.2, 4.4–4.5, 7 and 8. ADR-0005 §§3.5–3.7, 4.3, 6.2 and 7.2. ADR-0008 D3, D6 and D7. M06 plan U3–U4.
- **Problem.** Two separately enrolled issuers can know different issuance histories. A per-controller outbox sequence can collide with another controller's sequence unless the acknowledgement names its producer and effect. The first controller may report a residual from only its ledger. A pending revoke can also be held behind the mandatory reconnect time exchange, though durable denial can safely proceed even with uncertain time. The advertised offline bound omits the potentially earlier continuous-clock anchor and inherited deadline. Certificate expiry bounds new authentication with server-clock uncertainty. Owned admissions, dedicated sessions and detached processes have different residuals.
- **Smallest fix.** For V1 pin each grant to its issuing controller and CA, and use a separately approved grant for a different issuer. Allow either owner to deliver a narrowing effect. Namespace delivery by authenticated controller, effect ID and grant generation, and acknowledge only a durable runner tombstone with the local enforcement state. Let narrowing sync proceed with uncertain time and gate issuance/admission until the authority state is reconciled. Retain the accepted reserve/publish/install checks, including certificate key, issuer, principals, generation, scope and deadline. Compute readiness from the earlier derived anchor and certificate/deadline bounds, and retain the accepted per-component residuals plus an unknown or conservative bound while issuance history is unavailable.

### M06-D-R07 — Decide custody and recovery for the new keys

- **Blocking under ADR-0009 §2.1.** A copied state directory or ordinary removal can expose or destroy a durable device identity and affect remote admission.
- **Where.** ADR-0012 §§2.4–2.5, 3.3 and Q1–Q2. Spec §7.3. ADR-0005 §5 and ADR-0008 D1.
- **Problem.** Q2 proposes raw Unix key storage without a reviewed at-rest exception. An endpoint key can impersonate an admitted endpoint and reach a private sshd even though independent SSH authentication still applies. Q1 uses one management key per device but ties its destruction to client removal. Removing one runner registration could remove the management key for all of the device's runners. The design does not yet specify locked-store behavior, backup exclusion or recovery from loss.
- **Smallest fix.** Use existing verified platform storage for K_mgmt and K_iroh where available. For headless Iroh serving, explicitly rule on a narrowly scoped alternative under §7.3, including availability, backup exclusion, rotation, file ownership and recovery. Defer that serving profile if compliant custody is unavailable. Separate runner revocation from device retirement and use independently host-verified owner access to repair a lost pin. Keep K_env memory-only and K_ca on its issuing controller.

### M06-D-R08 — Align failover promises with raw SSH streams

- **Nonblocking under ADR-0009 §2.1.** With the trust checks above, a wrong availability guarantee causes a failed attempt rather than a consent or trust change.
- **Where.** ADR-0012 §§1.5, 5.3 and 9.6. M06 plan U5–U6. G06 S03 and S07. ADR-0006 §§5–6.
- **Problem.** A QUIC connection or locally opened stream does not prove the server has admitted that stream or connected to sshd. The raw Pigeons stream provides no readiness acknowledgement, and ordinary SSH can send its identification first. Counting only bytes delivered to ssh can replay bytes already sent to a failed route. OpenSSH also reports a ProxyCommand failure with its own exit, so the proxy's exit 3 or 4 cannot by itself express the public operation result.
- **Smallest fix.** Limit fallback to connection-establishment failures the helper can observe before forwarding in either direction. Once payload has been handed to a candidate, fail that attempt and keep OpenSSH in charge of host checks. Document late Iroh refusal and downstream failure as terminal for that attempt. Define a separate structured health or managed-operation result if callers need the cause, keeping helper exits internal and using the existing contract table for public results.

### M06-D-R09 — Prove runner dependencies by construction

- **Nonblocking under ADR-0009 §2.1.** The immediate gap is an unsupported unattended-readiness claim and lost work when a dependency disappears. It leaves A24 open.
- **Where.** ADR-0012 §§4.3–4.6 and 10. G07 §§4–6. M06 plan U3 and A24. Spec §§6.5 and 8.1.
- **Problem.** A socket pathname is a useful diagnostic for the tested sshd forwarding layout, but says little about provenance. An independently named local socket can still relay signing to the controller. Likewise a detached process survived on one session-scope configuration, while readiness only names the signer and clock conditions. A session-scope runner subject to active logind cleanup can lose its signer at logout. The fixed-key fixture showed operation through the observation window, and does not make arbitrary fixed access perpetual.
- **Smallest fix.** Launch from a clean environment with an explicit inventory of runner-owned sources. Require independently managed local key or signer custody for an unattended claim, and report arbitrary external-agent provenance as unknown unless verified. Make verified lifetime and dependency conditions part of readiness. Add one test using a controller-dependent signer with an ordinary local path, and distinguish detached-session evidence from actual user-service and restart evidence.

### M06-D-R11 — Keep G07 open for the mandatory runner and pairing outcome

## Consistency and scope

OpenSSH host/user authentication, endpoint identity and application authorization can remain distinct. The design keeps K_ca off workers, K_env in memory, native direct and ordinary single-hop bastion access independent of Iroh, and uninterrupted sessions outside the route-repair promise. The proposed ADR-0010 change is sound only as the explicit, narrow revision in R04. The current wording calls it no revision while introducing a command renderer for paths that can include a bastion. ADR-0006 revision 6 also needs explicit changes for attendance, authenticated caller namespaces and capability-required negotiation. No schema major bump is needed solely for additive shape changes, and supported earlier forms still need their existing behavior. Unavailable product rows remain unverified. A recorded scope decision is available for Iroh only.

## ADR-0012 §12 recommendations

- **Q1.** Use a persistent verified platform store for K_mgmt, with device retirement separate from runner revocation, because one device key can serve several runner enrollments.
- **Q2.** Use protected storage where verified and require an explicit headless custody ruling before persistent serving, because endpoint theft crosses the allowlist even with separate SSH authentication.
- **Q3.** Accept and disclose owner equivalence for the runner account. Use a separate account where operator isolation is a requirement.
- **Q4.** Keep n0 public off by default and make the profile opt-in after exact traffic and exposure evidence, because discovery, relay and direct paths disclose different metadata.
- **Q5.** Qualify Windows by independent native W1, W3 and W4 outcomes plus the in-box SSH path, because a loopback echo cannot verify relay certificate behavior, LAN prompting or SSH.
- **Q6.** Support the proved client-to-stock-roost direction as explicitly adopted external infrastructure and keep reverse interop unsupported, because rotating fly identities cannot meet the serving allowlist.
- **Q7.** Use a user service with owner-enabled linger where verified, because detached session lifetime depends on logind. Report any narrower lifetime.
- **Q8.** Carry the pinned, feature-scoped patch with upstream tracking and per-platform bind/path evidence, because the Linux trace supports the targeted fix and real NAT behavior remains open.
- **Q9.** Keep the accepted certificate bound without a new cap, because offline coverage is a user choice. Report the earlier safe runner deadline and each revocation residual separately.
- **Q-T.** Accept only fresh, nonce-bound responses from an authenticated and explicitly trusted owner time source tied to the runner and grant. Keep bounded RTT and a non-extending anchor, because possession of an approve permission does not establish clock validity.
