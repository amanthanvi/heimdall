## Findings

### M04-W2-R01 — High; blocking: a writable ancestor can redirect the returned SSH config to another account's file

**Locations:** [crates/wsl/src/bridge/linux.rs:354](crates/wsl/src/bridge/linux.rs) (handle-relative directory), `:375` (config write), `:401` (pathname socket bind), `:422` (returned paths); [crates/wsl/src/helper/mod.rs:189](crates/wsl/src/helper/mod.rs) (ancestors deliberately not checked).

**Scenario:** the fallback state base, XDG runtime base, or a relevant ancestor is writable/searchable by another Linux account, without sticky-directory protection preventing that account's rename. This is accepted: only the `heimdall` anchor and its descendants are checked. After one binding is live, that account renames `heimdall` aside and installs a replacement `heimdall/run/b/<tag>` with its own `ssh_config`. A known active tag suffices; for example, an owner's `ssh -F <config>` argv can disclose the path on a normal Linux `/proc` configuration. The attacker needs no access inside the old 0700 anchor.

On the next realization/recheck, legitimate files are rewritten through the old pinned `ManagedDir`, but the socket binds through the replacement pathname and the result returns the attacker's config path. The runtime's string equality check of the returned paths does not detect this identity mismatch. Using the descriptor with `ssh -F` executes a planted `ProxyCommand` as the owner. The same attack can pre-create a new binding's path if its tag is known; the existing-binding case does not depend on predicting a future random tag.

**Probe:** `path-isolated-final-probe.patch`, retained here, appends `review_probe_replaced_ancestor_returns_attacker_ssh_config`. It creates a disposable shared base before the helper starts, realizes `b1`, replaces the ancestor, and re-realizes that same tag/generation. It asserts (1) legitimate config exists under the displaced directory, (2) returned config contains the planted text, (3) the helper has bound a connectable socket under the replacement, and (4) `/usr/bin/ssh -F <returned config>` creates a harmless marker through the planted `ProxyCommand`. **Cargo exit 0, 1 passed**; the fixture SSH client itself exits **255** after running that command. The earlier new-tag variant also passed (exit 0, 1 passed). Sources and logs are retained as `probe-path.rs`, `path-probe.patch/.log`, and `path-existing-probe.patch/.log`; the final isolated rerun is `path-isolated-final-probe.patch/.log` (exit 0, 1 passed). The final SSH command explicitly disables identity, certificate, agent, known-host and multiplexing defaults.

The attacker actions in the probe run as the test account; it is a pathname/mechanism proof, **not a native second-UID test**. The cross-account applicability follows from directory rename/create permissions: every attack operation uses the shared parent/replacement tree, without opening the old private anchor. Root or the same Linux user can also do it, but neither is required in the shared-parent case.

**ADR-0009 §2.1:** blocks. Another account is a required adversary, and owner-context config execution gives it a capability it did not have, including lasting owner-data or remote-trust changes. This is not merely the accepted hostile-same-user residual. A private default home reduces exposure; it does not make an accepted shared ancestor safe.

**Smallest correction:** for Mode B, reject directory chains in which an untrusted principal can replace the exposed pathname's anchor/ancestors (accounting for sticky and ACL semantics), and make socket creation/removal and returned config paths refer to the same verified tree as file writes. Merely comparing the returned string, or adding one lstat before returning while continuing to accept a replaceable ancestor, leaves the race. Keep a regression that checks both the returned config contents and the actual socket location.

### M04-W2-R02 — Low; nonblocking cleanup defect: withdrawal during respawn can leave an ended endpoint recorded and served by the helper

**Locations:** [crates/runtime/src/wsl_bridge.rs:359](crates/runtime/src/wsl_bridge.rs) and `:373` (respawn snapshot/replay), versus `:401` (post-realize membership check used only by live rechecks); the ordinary `WslRealizer::realize` at `:560` also lacks that post-call check.

**Scenario:** bindings A and B share the helper. Its respawn snapshots both desired tags. A ends while A's realize is in progress: withdrawal removes A from runtime state and asks the new helper to withdraw it before the delayed realize completes. The stale realize then recreates A. Because B remains live, the helper remains alive. Later live rechecks iterate desired tags only, so they do not sweep this orphan.

**Probe:** independently reran `respawn-probe.patch` as `review_probe_withdraw_during_respawn_returns_an_ended_endpoint`: a synchronous fake-bridge hook clears A at that exact point in the production supervisor path. **Cargo exit 0, 1 passed**. Assertions establish that the runtime endpoint registry has removed A, the helper's realized set still contains A, an attempted open cannot obtain a signer, and another tick leaves A recorded. See `respawn-probe.patch/.log`.

**ADR-0009 §2.1:** does not block. An ordinary cleanup/respawn race triggers it, so the absolute no-resurrection claim is false, but the demonstrated effect is a stale socket/public material and helper state. The environment/tag lookup and endpoint registry refuse the signer. No lasting remote authority, owner-data change, durable recovery-record corruption, or consent bypass was demonstrated. This is a nonblocking correctness defect, not a claim that the signer resurrects.

**Smallest correction:** reuse `realize_again`'s generation/membership post-check for respawn replay, and apply the same check to first realization. Withdraw a realized generation that ceased to be desired while the call was in flight. No new registry abstraction is needed.

### M04-W2-R03 — Medium; blocking consent defect: the no-start rule is a snapshot check followed by a start-capable launch

**Locations:** [crates/wsl/src/bridge/session.rs:178](crates/wsl/src/bridge/session.rs) through `:183`; [crates/wsl/src/host.rs:253](crates/wsl/src/host.rs) (wslpath resolution), `:303` (helper launch); [crates/runtime/src/wsl_bridge.rs:490](crates/runtime/src/wsl_bridge.rs) (background respawn).

**Scenario:** a helper has died while the distribution is running. A supervisor tick reaches `Bridge::start(Forbidden)`, whose running listing says Running. The owner then terminates the distribution, or it stops, before `launcher.launch`. `Forbidden` is not passed to `launch`; the production launcher executes `wsl.exe -d ... --exec /usr/bin/wslpath ...` and then `wsl.exe -d ... --exec <helper> ...`. Those commands can cold-start the now-stopped distribution. A second pre-launch listing would only narrow the window.

**Probe:** `review_probe_forbidden_start_uses_a_stale_running_snapshot` in `extra-probes.patch` runs the real `Bridge::start(Forbidden)` against a launcher that returns the earlier Running snapshot while marking the fixture stopped before launch. Launch is still called, the real helper loop starts, and realization succeeds. **Cargo exit 0, 2 passed** for the combined extra-probe command (this case plus R04). This proves the production control flow lacks an atomic no-start boundary. **The real wsl.exe cold-start consequence is source/command-semantics inference, not an observed native WSL run.**

**ADR-0009 §2.1:** blocks under the literal explicit-start rule in ADR-0010 §11 item 1. The trigger is the owner's ordinary termination/stop, and a background request crosses a boundary reserved for an explicit owner start. Blocking here rests on consent, not on an assertion that the probe demonstrated data loss. The request-led Mode A check/launch pattern predates this wave; the new background Mode B respawn makes this an unattended path in the reviewed change.

**Smallest correction:** use a launch mechanism that cannot start a stopped distribution. If that capability is unavailable, fail closed by requiring an explicit owner `ensure` for a fresh helper launch after loss, or obtain a contract-owner ruling that explicitly narrows the absolute no-background-start promise and records the race. Another listing is not a complete correction. This authority-semantics choice needs the contract owner's ruling; this review does not silently relax it.

### M04-W2-R04 — Low; nonblocking: the Git descriptor does not quote its config filename

**Location:** [crates/app/src/operations/container_m04.rs:847](crates/app/src/operations/container_m04.rs).

**Scenario:** an accepted Linux path contains a space, such as `<run base>/with space/.../ssh_config`. The descriptor returns `GIT_SSH_COMMAND=ssh -F <path>` without shell quoting. Git splits the filename into separate arguments, so the advertised Git flow cannot use that binding. Shell metacharacters in a same-user-selected base can also be interpreted by the shell.

**Probe:** `review_probe_git_descriptor_splits_a_config_path_with_spaces` in `extra-probes.patch` calls the production descriptor function, then runs real Git `ls-remote` with an inert scratch `ssh` that records argv and exits 1. **Combined Cargo exit 0, 2 passed**. Git exits **128**; the probe asserts that the filename became two arguments and the complete config filename never reached SSH. There is no network connection or personal Git config. See `probe-extra.rs` and `extra-probes.log`.

**ADR-0009 §2.1:** does not block. The ordinary whitespace case is an availability failure. The metacharacter case, when it requires a hostile same-user-selected base, grants that program no new capability; no independent cross-account injection beyond R01 is claimed.

**Smallest correction:** shell-quote the entire config path as one POSIX argument when composing `GIT_SSH_COMMAND`, including embedded single quotes. Keep raw paths unchanged in the descriptor's path fields.

## Answers to questions 1–6

### 1. Socket and transport security

- **Other Linux users:** with a stable private directory chain, directory 0700/socket 0600 deny access, and `connection` checks the real effective helper UID through `peer_cred` before reading a byte ([crates/wsl/src/bridge/linux.rs:610](crates/wsl/src/bridge/linux.rs)). This uses the actual UID, not the injected test hello identity. On Linux Tokio uses SO_PEERCRED; this Mac exercised its Unix peer-credential implementation. R01 breaks the path/config guarantee for another account able to replace an ancestor, although the UID check still prevents that account directly obtaining signatures as its own UID.
- **Other distributions/Windows:** there is no TCP/abstract-/mnt/wsl bridge listener or Windows binding pipe. The runtime/helper exchange uses the parent-child stdio channel and existing explicit Windows handle inheritance. A different distribution with no access to that filesystem and no interop escape has no endpoint by design; this was not natively verified here. A process of the same Windows user **can** enter the target distribution/account with `wsl.exe -u` and use a live binding's signatures. A Linux user able to use such interop can do likewise; distribution root can become the owner. These are disclosed non-claims, not isolation properties. Another Windows account's refusal remains a native-platform claim not proved on this Mac. None of these paths exposes the personal agent, CA key, or control API.
- **Messages:** the helper reads a bounded nonzero four-byte-length agent frame and applies the existing classifier before opening a stream. Add, remove, remove-all, lock/unlock, smartcard, unknown extensions/types are refused locally. There is one intentional qualification to “only list and sign”: **`session-bind@openssh.com` is also allowed**, consistently with the existing signing contract ([crates/ipc/src/signing.rs:85](crates/ipc/src/signing.rs), `:109`). Other extensions are refused. Classification recognizes list/sign by type; malformed bodies of those types can reach the runtime parser, which must refuse them. This is not a new operation-class bypass. Zero/over-256-KiB lengths and truncated frames close the connection; the integration test specifically exercises the oversized case. Runtime `serve_with_limits` classifies again. No control/issuer request dispatch exists on this socket.
- **Creation and path replacement:** `ManagedDir` creates/verifies the binding directory as 0700 without following child symlinks. Socket bind precedes chmod to 0600 (`linux.rs:516`); normally the parent already prevents traversal during that window, and the peer UID check remains before any protocol bytes if a connection is queued. R01 means that parent assumption cannot be generalized to a replaced ancestor. Files use pinned handles, but socket lstat/bind/chmod/unlink and returned paths use strings. Existing generation checks protect ordering only within that selected tree. The same-generation socket-presence check tests UID only, not socket type/inode; same-user replacement/denial remains possible. UID-only unlink is not inode-pinned, so no race-proof claim about replacement sockets is established. Another user's pre-existing socket or a non-socket found by `occupant` is normally refused and preserved; a protected child symlink is refused. R01 is the additional cross-account path hazard.
- **Limits:** the real helper test passed the 65th-connection refusal, retained the first 64, verified modes, listed one fixture identity, produced a cryptographically verified fixture signature, and demonstrated that rejected messages did not reach the Windows-side handler.

### 2. Lifetime

An ended/revoked binding cannot obtain new signatures through the reviewed stream-serving path: the environment's desired tag must still map to a live registry entry/generation, and the ManagedSigner checks current authority on requests. Grant/policy/deadline checks remain in the runtime; the helper intentionally does not trust/enforce the Linux deadline. R02 nevertheless shows a physical endpoint/helper record can return and survive later ticks after withdrawal. The absolute “never comes back or stays recorded” claim is false.

Normal grant-end withdrawal, exact-generation withdrawal, helper EOF/shutdown cleanup, killed-helper stale cleanup, deleted-socket repair, running/stopped supervision, and twice-missing GUID retirement passed their respective tests. `wsl disable` retires the managed environment and stops its endpoints/helper; uninstall dispatches disable for Mode A and Mode B with `start=false` (the added CLI unit test also passed). A stopped distribution can retain dead sockets/public files with `cleanup_pending`. The in-memory pending-cleanup loss across runtime restart is an explicitly documented §11 residual; it must not be described as durable cleanup tracking. No working signer after disable/uninstall was demonstrated.

Runtime startup wires the bridge before managed reissue; the existing reissue eligibility path rejects ended/tombstoned/expired authority and retries failed eligible restorations. This was source-traced and the requested 54-test M03 integration target passed. A complete WSL-specific runtime-restart matrix was **not** executed. Higher-generation reissue on existing Mode B endpoints remains the documented fail-closed limit.

For starts, stopped-at-check distributions are refused under Forbidden, as the existing tests prove; R03 is the unclosed stop-between-check-and-launch case. Explicit `wsl disable --start` is an authorized exception. Also, the pre-existing CLI `wsl enable` account discovery can run `id -un` inside the named distribution if `--account` is omitted ([crates/heimdall/src/wsl_cmd.rs:162](crates/heimdall/src/wsl_cmd.rs), `:225`); it may start it during that explicit setup request. Thus “nothing except ensure can ever start a distribution” is too broad even aside from R03. The attended Mode B enable fixture supplies `--account` and does not test default-account discovery.

### 3. Consent and scope

No new-environment enable bypass was found. `wsl_request` requires Owner; fresh Mode B enable makes/join-coalesces an `AddEnvironment` decision. The CLI attends, shows the recorded decision/disclosures and requires typed confirmation before approving. The application decision path checks attendance and applies the environment and distribution records transactionally; denying or leaving the decision pending does not add the environment. Idempotent enable for the already-approved account does not require another widening decision; conflicting accounts are refused.

New environments receive `managed_signing=true`, `automatic_activation=false`, `issuer_access=false`. Ensure still enters managed-set admission and the existing authority/policy pipeline. No scope expansion beyond policy was found. The test's direct policy/environment edits, described below, are fixture setup rather than proof of a product policy-editing UX. R03 concerns starting an already-enabled stopped distribution without the explicit start, not adding an unapproved managed environment.

`distribution_projection` apply/rollback previews fail with `driver_unavailable` through `distribution_form` ([crates/app/src/setup.rs:769](crates/app/src/setup.rs)), and the requested runtime refusal table passed. Mode B returns a per-binding config and writes no distribution `~/.ssh` projection.

### 5. Late frames

No cross-stream or cross-binding delivery was found. Each helper session allocates odd increasing stream numbers; `may_open` rejects reuse/non-increasing/even numbers, and the stream map permanently associates each live number with its chosen binding handler. Data/close for a removed old ID are dropped rather than retargeted. Above-highest/even IDs are violations. `stream_ref` also drops unused odd gaps below the highest, although its comment calls these previously opened; that imprecision does not deliver anything. IDs are not recycled across bindings; a new helper has a new channel/table. No practical wraparound path was demonstrated. Pure protocol/channel tests passed; the classifier revert proof established the local filter rather than relying only on the downstream signer.
