### M04-W1-R01 — Blocking (High): Routed (`ProxyJump`) enrollments silently skip host-key change detection in `reverify_due` and `evaluated_host_key_changed`
- **Locations:**
  - [crates/app/src/enrollment.rs:734-761](crates/app/src/enrollment.rs#L734-L761) (`host_key_changed_via` added and unit-tested at `:1089-1090`, while `host_key_changed` delegates to `host_key_changed_via(..., None)`)
  - [crates/app/src/operations/enrollment_m03/passes.rs:179-184](crates/app/src/operations/enrollment_m03/passes.rs#L179-L184) (`reverify_due` calls `host_key_changed(&r.target, &t.evaluate(a))` with `expected = None`)
  - [crates/app/src/operations/enrollment_m03/verify.rs:236-244](crates/app/src/operations/enrollment_m03/verify.rs#L236-L244) (`evaluated_host_key_changed` calls `host_key_changed(&ctx.record.target, &t.evaluate(&ctx.alias))` with `expected = None`)
- **Scenario:**
  1. An owner enrolls and verifies destination `ex2` directly, configures `--jump ex1` (`ProxyJump exit1`) and runs `setup apply`, and receives an active grant via `ensure --require-destination-scope verified_server_principals`.
  2. The final host (`ex2`)'s key changes in `known_hosts` (rotation or MITM).
  3. Although `route::evidence_survives` prevents *new* `ensure` calls that require verified scope from succeeding, `host_key_changed_via` is never called by either enrollment verification path:
     - **Supervisor pass (`reverify_due`, `passes.rs:181`):** Because `eval.proxy == ProxyRoute::Jump` and `expected == None`, `host_key_changed` returns `false`. The supervisor never opens `enrollment.verify`, never moves the enrollment from `Verified` to `Held(HostKeyChanged)`, and never degrades active grants via `degrade_grants_under_ca` (`verify.rs:632`).
     - **Manual or 80-day `enroll verify` (`verify_once`, `verify.rs:176-184`):** `evaluated_host_key_changed` (`verify.rs:242`) also returns `false`. Instead of short-circuiting before any session/certificate (ADR-0008 §17.22 item 7), `verify_once` enters `run_verification` (`verify.rs:265`), mints `K_verify` positive and negative certificates, and spawns direct `ssh` without `ProxyJump`. On a bastion-isolated destination (not directly reachable without `ProxyJump`), this ends with `verification_inconclusive` (leaving the enrollment `Verified` and active grants un-degraded); on a directly reachable destination, it launches an unapproved direct SSH session against a host whose key changed.
- **Probes (temporary reproducers run and reverted):**
  1. Real-binary probe (`probe_m04_w1_r01_routed_verify_on_key_change` added temporarily to `tests/e2e/route_m04.rs`): with `ex2` enrolled, verified, `--jump ex1` applied, active grant issued, final loopback sshd stopped (bastion-only topology), and `[127.0.0.1]:{final_port}` key replaced in `known_hosts`:
     - Command: `TMPDIR=/tmp cargo test -p heimdall --test e2e_route_m04 probe_m04_w1_r01_routed_verify_on_key_change -- --exact --nocapture`
     - Result: **exit code 0** (`PROBE_R01: verify_code=4 verify_reason=verification_inconclusive state_after=verified grant_degradation=None`). `enroll verify` skipped evaluation detection, attempted verification, failed inconclusive (`code=4`), kept enrollment `verified`, and left the active grant un-degraded (`None`).
  2. Supervisor probe (`probe_m04_w1_r01_reverify_pass_skips_routed_host_key_change` added temporarily to `tests/e2e/enroll_m03.rs`): on a `Verified` enrollment whose evaluator returns `ProxyRoute::Jump` (`proxy_jump: Some("bastion")`) and a changed final host key:
     - Command: `TMPDIR=/tmp cargo test -p heimdall --test e2e_enroll_m03 probe_m04_w1_r01_reverify_pass_skips_routed_host_key_change -- --exact --nocapture`
     - Result: **exit code 0** (`PROBE_R01_REVERIFY_PASS: done=[] state_after=Verified grant_degradation=None`).

### 2. WSL Durability (`ADR-0010 §9 item 2`)
- **Durable before acknowledgment:**
  - Inside the helper, `ProxySink` ([crates/wsl/src/helper/mod.rs:338-350](crates/wsl/src/helper/mod.rs#L338-L350)) sends `Frame::SinkAppend` / `Frame::SinkCommit` over stdout and blocks on `Frame::SinkAck` / `Frame::SinkFailed` before returning from `StageSink` calls.

- **Lost-reply reconciliation without double-apply:**
  - [crates/app/src/setup.rs](crates/app/src/setup.rs) (`reconcile_op`) reads durable receipts and journaled `StepContent` and reconciles against a fresh helper (`OutcomeUnknown` recovery / interruption after receipt before commit), verified by `integration_wsl_helper_channel`.

- **Generation-scoped rollback preserving user edits:**
  - `StepContent` generation/SHA-256 digests and `CommitItem` ownership let rollback/cleanup remove only the recorded generation block while preserving later user edits.

### 5. Store Namespace Guard
- **Location:** [crates/store/src/ext.rs:2204-2231](crates/store/src/ext.rs#L2204-L2231) (`Txn::commit_projection_item`).
- **Verification:** A cross-environment projection item commit (`op.environment != commit.record.environment`) is admitted **only** when BOTH:
  1. `op.kind.is_setup()`,
  2. `self.self_environment()?.as_ref() == Some(&op.environment)` (the operation belongs to the runtime's own native environment), AND
  3. `self.wsl_distributions()?.iter().any(|r| r.namespace.as_ref() == Some(&environment))` (the target namespace belongs to a registered WSL distribution of this store).
  - Container environments are full managed environments (`op.environment == commit.record.environment`), so no cross-environment exception is granted to or from container namespaces; every foreign or non-WSL cross-environment commit is refused.

- **Does Windows `state_dir_unsafe` break a supported real-world case?**
  - **Pre-M04 Windows installs / inherited-ACL `<home>/state`:** Any M01–M03 Windows `<home>/state` directory created before M04 W1 (or any directory under `%LOCALAPPDATA%` inheriting `SYSTEM`/`Administrators` ACEs or lacking `SE_DACL_PROTECTED`, [crates/runtime/src/platform.rs:1244-1260](crates/runtime/src/platform.rs#L1244-L1260)) is now refused with `state_dir_unsafe` and never repaired. By ADR-0010 §1 item 7 this refusal is deliberate for runtime start, and M01–M03 had no shipped Windows package/release (installers/upgrades are M08).
  - **Uninstall / rollback breakage (`M04-W1-R02`):** Because `client::connect_as` swallows `StateDirUnsafe` (`client.rs:183`) and `uninstall` calls `connect_requiring(ctx, true, ...)` when `state.db` exists (`uninstall_cmd.rs:2420`), any Windows user hitting `state_dir_unsafe` is blocked from running `heimdall uninstall` or `heimdall setup rollback` to cleanly undo Heimdall's `~/.ssh/config`, `~/.gitconfig`, and `HKCU\...\Run` changes before removing `<home>/state`.
  - **Other residuals noted (already recorded in `ADR-0010 §10`):** Windows `spawn-lock` window on remaining `Command::spawn` call sites, brief console flash on Windows `Run` login (`FreeConsole`), and sub-uid container `0700` dir traversal vs rootful peer-uid test coverage.
