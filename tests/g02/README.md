# G02 shared conformance harness

One harness judges all three G02 prototypes (Go + Bubble Tea, Rust + Ratatui, TypeScript + OpenTUI)
identically against the frozen slice contract `docs/g02/slice-contract.md`, **including §9 "Clarifications"
K1-K12, K3a, §9.1 round-2 rulings K6a, K10 (confirmation), K13-K16, §9.2 K6b, K6c and §9.3 round-3 rulings K6d, K6e,
K17, K18, K10 exit form and the start-up window** (harness version 2.3.0), and emits a plan.md §6.6 evidence record
per candidate and platform. K13: a candidate passes the common slice only if the full harness passes on
darwin-arm64 **and** linux-arm64; the Linux record comes from `linux/run.sh` (below). It also contains the
instrumented fake SSH agent reused by later gates.

Supports: R-SS-04 (byte-clean streams, process behaviour), R-SS-02 (agent contact recording for the later
A21 passivity proof), R-SE-05 (malformed parser/IPC/argv input), R-QU-07 (traceable evidence, nothing marked
passed without a run). A record naming these ids is never by itself evidence that a requirement is met
(tests/evidence/README.md); self-test records (`--selftest`) carry no requirement ids.

Status of this deliverable: see `SELFTEST.md` (generated by `selftest.py`, real exit codes only). The harness is
validated against `reference_impl.py` / `reference_tui.py` and their injectable defects (`REF_MUTATE`).

## Running

```sh
# one-time, only needed for the tui.* / pty checks (installs into tests/g02/.venv, git-ignored)
python3 -m venv tests/g02/.venv
tests/g02/.venv/bin/pip install --require-hashes -r tests/g02/requirements.txt

# judge a candidate (python3 >= 3.11 for tomllib; the venv is found automatically)
python3 tests/g02/conformance.py \
    --bin prototypes/go/dist/darwin-arm64/heimdall-proto \
    --candidate go \
    --out tests/evidence/G02-go-conformance.json \
    [--artifacts-dir tests/evidence/artifacts/G02-go-conformance] \
    [--only agent.*,run.forward_sigterm]

python3 tests/g02/conformance.py --list        # check ids
python3 tests/g02/conformance.py --list-md     # markdown catalogue (the table below)
python3 tests/g02/selftest.py --repeat-baseline 2 --linux
                                                     # re-prove the harness on macOS and in the Linux container
```

Exit code: 0 only when every selected check ran and passed; 1 if any check failed, errored or was skipped;
2 for harness usage problems; **3 if the final canary self-check found a full `HEIMDALL_CANARY_` value in the
record or in an artifact written by this run** (the values are redacted before anything is written, the record
gets `status: in_progress`, `verdict: inconclusive` and a limitation naming the JSON paths/files and canary
labels; the evidence is invalid and the harness defect must be fixed).

Other options: `--case-id`, `--build-commit`, `--environment-extra JSON` (merged into `environment`),
`--path-map CONTAINER=HOST` (container paths in `evidence_paths`/`environment.binary`), all used by the Linux runner.

## Linux runner (K13)

```sh
# full catalogue against a candidate's linux-arm64 artifact directory (executable plus sidecars)
tests/g02/linux/run.sh --artifact-dir prototypes/go/dist/linux-arm64 --candidate go \
    --out tests/evidence/G02-go-conformance-linux-arm64.json [--artifacts-out DIR] [--only IDS] [--case-id ID]
# harness self-test record against the reference implementation (REF_MUTATE / HM_G02_HARNESS_MUTATE passed through)
tests/g02/linux/run.sh --reference --out /tmp/ref-linux.json
# the whole self-test inside the container (selftest.py --linux calls this)
tests/g02/linux/run.sh --selftest /tmp/linux-selftest -- --repeat-baseline 1
tests/g02/linux/run.sh --build        # build if needed, print image reference and id
```

* Image: `linux/Dockerfile`, base `python:3.13-slim-bookworm@sha256:5024f48b…` (multi-arch index digest, the
  linux/arm64 manifest is Debian 12 + CPython 3.13.16), `openssh-client=1:9.2p1-2+deb12u10` (ssh-keygen,
  `ssh -V`), `locales=2.36-9+deb12u14` (en_US.UTF-8) and `zsh=5.9-4+b15` (K6e forms under zsh, non-gating; added in
  harness 2.3.0, image tag changed accordingly) pinned by Debian version, `pyte`/`wcwidth` installed with
  `pip --require-hashes -r requirements.txt`, user `g02` (uid 10001). Build context `tests/g02`, of which only
  `requirements.txt` is sent (`Dockerfile.dockerignore`). The tag is the first 12 hex digits of the sha256 of the
  Dockerfile, the dockerignore and requirements.txt (`heimdall-g02-harness:<tag>`); the image is built once and
  reused, never pushed. Debian dependency versions follow bookworm at build time; every record stores the image
  id, base digest and the installed package versions, so a rebuilt image is recognisable.
* Run: `docker run --rm --platform linux/arm64 --network none --user 10001:10001 --cap-drop ALL
  --security-opt no-new-privileges --memory 2g --pids-limit 4096`; the repository is mounted read-only at
  `/repo`, the artifact directory read-only at `/artifact` (whole directory, so sidecars resolve from the
  executable's own directory, K11), and only the output directory (and the artifacts directory) writable. The
  runner refuses an image or Docker server that is not arm64 (K13: native arm64 kernel, not emulation).
* Record: same format as a host run; `case_id` defaults to `G02-<candidate>-conformance-linux-arm64`
  (`G02-harness-selftest-<candidate>-linux-arm64` for `--reference`), `environment.platform` is `linux-arm64`,
  `environment.container` holds image ref/id, base image digest, package versions, Docker server version,
  network, user, capabilities and mounts; `build_commit` is the host's `git rev-parse HEAD` (+dirty). Default
  artifacts directory: `<out dir>/artifacts/<case_id>`.
* Platform gating: on Linux `agent.reset_before_reply` / `agent.reset_after_partial_header` require (gating
  precondition) that the fake agent's reset reaches the reader as `ECONNRESET`, so K3a is judged on the real reset
  path; on Darwin the delivery is a non-gating observation (Darwin delivers EOF). `run.k6a_inherited_ignore` also
  checks the child's `/proc/self/status` SigIgn mask on Linux; `rss_wrap` converts `ru_maxrss` units per OS.

Canary rule (`tests/evidence/README.md`): no record or artifact may contain a full `HEIMDALL_CANARY_…` value.
The fixture canaries (`invalid-forbidden-key.toml` key `private_key`, `invalid-unknown-dest-key.toml` key
`destinations[0].identity_file`) are read from the fixtures at run time; the environment canary (in
`HM_G02_SECRET_ENV`), the `[meta]` canary and the malformed-line canary (`profile.error_value_not_echoed`) are generated per run. Values exist only in memory; assertion text
names a canary by fixture and key path. Captured output is redacted before it is stored, notes are redacted,
console progress lines are redacted, and after the record is built the harness scans every string of the record
and every artifact file this run wrote for any registered value or any prefix followed by a value character
(exit 3 above). `harness.canary_selfcheck` unit-tests the scanner; the self-test's harness mutations
`canary_in_desc` (the round-1 defect: a canary value in assertion text) and `canary_in_artifact` (an unredacted
artifact) prove the self-check fires and leaves nothing on disk.

Evidence record (gate-probe convention of `tests/evidence/README.md`): `status` describes the evidence -
`verified` when the full catalogue ran with no errored or skipped check (whatever the outcome), `in_progress`
for a partial (`--only`), pyte-less or errored run. `observed_result.verdict` is `pass` (full run, every check
passed), `fail` (at least one check failed) or `inconclusive`. `observed_result` holds the per-check table: id,
contract clause / K id, hard bound, every assertion with expected versus observed, each captured invocation
(argv, real exit code, elapsed ms, sha256, redacted truncated stdout/stderr), plus latency observations
(first frame, resize re-layout, large-100 keystroke-to-update, SIGINT-to-exit).

Isolation: every run builds a private sandbox under `/tmp` (deleted afterwards, also when the harness gets
SIGTERM) with its own empty `HOME`, `TMPDIR` and working directory. The binary's environment is built from
scratch (`PATH`, `HOME`, `LANG`, `LC_ALL`, `TMPDIR`, `TERM`, `HM_G02_SECRET_ENV` carrying the per-run canary) - the harness's `SSH_AUTH_SOCK`
and the real `~/.ssh` are never visible. Keys are generated per run with `/usr/bin/ssh-keygen`, private halves
deleted immediately, fingerprints cross-checked with `ssh-keygen -lf`. `--pass-env` exists solely for the
self-test.

## Robustness guarantees (harness defects fixed in M00-T05)

* **(a) Double-width cells.** pyte 0.8.2 stores a wide character plus an empty "stub" cell and its
  `Screen.display` assumes the pair is never split. A narrow character written over the left half (exactly what
  Ratatui's diff emits for `vps-東京`) left an orphan stub and `display` raised `IndexError`; a character written
  over the right half was hidden. `harness_lib.make_screen` renders lines with xterm semantics instead (the
  damaged half of a split wide character is blank). Regression: `harness.screen_wide_chars` (unit cases plus the
  literal byte sequence the Rust prototype emitted; stock pyte's behaviour on the same input is recorded as a
  non-gating observation: IndexError / hidden text). End to end: `reference_tui.py` now renders with a
  Ratatui-style cell diff that overwrites only the left half of `東`/`京` when a filter blanks the `vps-東京` row,
  so the baseline TUI checks exercise the fix (replaying their recorded output through stock pyte raises
  IndexError for 7 sessions, the same 7 checks that errored for the Rust prototype).
* **(b) Undrained pty output.** On macOS a process that exits, or a session leader that closes its controlling
  terminal, with undrained pty output blocks in exit until the output is read. `PtySession.close` used to block
  in `wait()` without reading the master (observed: the run hung indefinitely in `tui.filter_matches_host`).
  `close()` now drains while waiting, escalates to SIGKILL and finally hangs the terminal up, all within a
  budget; `send()` writes non-blocking while draining and raises `HarnessStall` instead of blocking on a full
  input queue; the command's stderr pipe is drained too (and canary-scanned), and the harness's own slave
  descriptor is closed non-blocking after the master so its last close cannot wait for a drain either.
  Regression: `harness.pty_close_undrained` (killed-while-writing, exited-with-queued-output, stalled reader;
  it also runs the legacy non-draining teardown on the same scenario and records, non-gating, that on macOS it
  is still blocked after 2 s - the original defect).
* **(c) Hard wall-clock bound.** Every check runs under a SIGALRM bound (default 120 s, overridable per check)
  and its cleanup under another (30 s); `CheckTimeout` is a `BaseException`, so `except Exception` blocks cannot
  swallow it and it interrupts blocking syscalls. A check that hits a bound is recorded as `error`, never pass.
  Afterwards every still-unreaped process the harness started is SIGKILLed by process group (only unreaped
  processes, so a recycled pid is never signalled). `communicate()` and agent `stop()` are bounded too.
  Regression: `harness.check_bound` (a check blocked in `waitpid` and a blocked cleanup are both cut off).
* **(d) Canary values in evidence (M00-T05-harness-r2).** Round-1 `profile.invalid_forbidden_key` and
  `profile.invalid_unknown_dest_key` put the full fixture canary values into assertion descriptions, so every
  evidence record leaked them (expected/observed were redacted, descriptions were not). Assertions now name the
  canary by fixture and key path, values are loaded from the fixtures into memory only, the env/[meta] canaries are
  per-run random, notes and console lines are redacted, and a final self-check scans the record and every artifact
  written (exit 3). Regression: `harness.canary_selfcheck` plus the self-test's harness mutations
  `canary_in_desc` (re-introduces the round-1 defect) and `canary_in_artifact`.

* **(f) Round-4 gaps found by the round-2 prototype reviews (M00-T05-harness-r3, contract §9.3).** The final G02
  verdicts must rest on the harness, not on reviewer probes. Each gap has a reference mutation the self-test
  requires the named check to catch, on macOS and in the Linux container:
  * K6d shared mode (the Go review: in "shared mode" an explicit `kill -INT/-HUP/-QUIT/-WINCH <pid>` was silently
    lost). New `run.k6d_shared_mode_explicit_signals`: heimdall-proto as the child of a foreground non-job-control
    `/bin/sh -c` script, and as the first and the last member of a `bash -i` pipeline job; each of SIGINT, SIGTERM,
    SIGHUP, SIGQUIT, SIGWINCH sent with `kill(<heimdall-proto pid>, sig)` (pid taken from the child's ppid and

    recorded (`observations.k6d_shared_mode_deliveries`, duplicates allowed per K6b), the exit statuses must be the
    child's. Mutation `run_shared_drop` (a Go-style shared mode that drops the four terminal-type signals).
  * K6e job control (the Go review: on Linux, Ctrl-Z then `fg` re-stopped the job). New `run.k6e_job_control`: in
    `bash -i`, the run job as a simple command and inside a command list (`run ...; echo`, the reviewer's form),

    child not in state T, and the next typed line reaches the child) and Ctrl-Z/`bg`/`fg` (child in a heartbeat loop

    typed line as before); finally the job's status is 0 and no job is left. Mutation `run_fg_restop` (a later

  * K17 filter latency: `tui.large_100_filter_latency` now measures 30 filter edits (5 cycles of `7`, `0`, `5` and

  * K10 exit form (Q8): `tui.sigterm_restores_terminal`, `tui.sighup_exit_129` and `tui.hangup_exit_129` accept the

## Instrumented fake agent

`python3 tests/fixtures/fake-agent/fake_agent.py --socket PATH --mode MODE [--pubkey FILE ...] --log FILE --ready-file FILE`

Modes: `normal empty slow oversize huge_nkeys truncated trailing_bytes wrong_type failure invalid_utf8_comment`,
boundary/robustness modes `string_overrun comment_overrun nkeys_max nkeys_over frame_max frame_over fragmented`,
the round-3 framing/timing modes `zero_length_frame` (header declaring length 0, no type byte),
`answer_type_only` (type-12 frame of length 1), `answer_short` (type-12 frame of length 3), `nkeys_short` (nkeys 3,
within the bound, one key present) and `drip` (the normal answer, one byte every 100 ms; the connection stays open),
and the §9 modes `control_chars` (K1: key type and comment with ESC, TAB, DEL, BEL, SOH, U+0085, U+009B and one
invalid byte), `close_silent` (K3: read the request, close without a byte), `partial_header` (K3: one header
byte, then close), `failure_payload` (K4: type-5 frame of length 5), `reset_before_reply` and `reset_after_byte`
(K3a: peek at the request without consuming it, optionally send one header byte, then close with `SO_LINGER 0`
and the request still unread). Linux reports such a close to the peer as `ECONNRESET` (after any byte already
queued); Darwin AF_UNIX stream sockets never report a reset, the peer sees EOF in the same position (measured
2026-10-03: SO_LINGER 0, unread data and closing a listener with a pending connection all give EOF/EPIPE).
`harness.fake_agent_modes` verifies the exact bytes each of these puts on the wire and records how the OS
delivered the reset.
It never signs, answers any non-type-11 request with `SSH_AGENT_FAILURE` after logging it, accepts spaced and
Unicode socket paths, and on SIGTERM/SIGINT closes connections, removes the socket and exits 0.

Contact log (JSON lines): `listen`, `connect{conn}`, `message{conn,type,length,bytes,responded,sent_bytes}`,
`disconnect{conn,reason,bytes_received,bytes_sent,partial_bytes}`, `shutdown`; each with UTC `ts` and
`mono_ms`. `disconnect.reason` is `peer_eof`/`peer_reset` only when the client closed the connection;
`server_shutdown`/`server_close`/`server_reset` otherwise (`server_reset` events carry `request_left_unread: true`). A passivity proof for A21 is: exactly one `connect`, exactly one
`message` of `type` 11 with `bytes` 5, `bytes_received` 5, `partial_bytes` 0
(`harness_lib.passive_report`), or zero `connect` events where no contact is allowed.

## Known harness limitations

* Windows is NOT covered: named-pipe agent path, CommandLineToArgvW quoting, console Ctrl-C and ConPTY behaviour need a native Windows run (blocked_on: native Windows host). `conformance.py` refuses to run on non-POSIX hosts.
* WSL is NOT covered (blocked_on: Windows host with WSL).
* Linux is covered only as Docker Desktop's linux/arm64 VM (linuxkit kernel 7.0.x, native arm64) inside the pinned
  Debian 12 image (`linux/run.sh`); other kernels, distributions, x86-64 and bare-metal Linux are not exercised.
  The linux-x64 artifacts are not judged. Docker Desktop bind mounts (virtiofs) carry the repository, artifact and
  output directories; the sandbox itself is in the container's `/tmp`.
* K3a on macOS: Darwin never reports `ECONNRESET` on an AF_UNIX stream socket, so `agent.reset_*` against a macOS build only exercise the EOF-equivalent path (the record's `limitations` and `observations.k3a_reset_delivery` say so). K13 moves the K3a judgement to the Linux record, where the reset delivery is a gating precondition.
* K6a is judged on three scenarios only: a pipeline job of `bash -i` (bash 3.2 on macOS, bash 5.2 in the image) whose peer reads the tty, a non-job-control script whose `&` job is heimdall-proto (stdin the tty or /dev/null), and inherited SIG_IGN for SIGHUP and for SIGINT (gated, K6c; other inherited ignores - SIGQUIT, SIGTERM, SIGWINCH with a CPython child, SIGPIPE with a non-Python child - and an inherited blocked SIGUSR2 are recorded, not gated). Other shells (zsh, fish, dash) and nested job control are not tested. With an ignoring child, "not forwarded" is observable only through the child's own handler (phase 2 of `run.k6a_inherited_ignore`).
* K14 uses a FIFO without a writer, a listening AF_UNIX socket, a directory and `/dev/null`; blocking or infinite devices (`/dev/zero`, a tty) are deliberately not used. The tui variant's 2 s includes the pty shim's start-up.
* K15 wall time is measured by `rss_wrap.py` from spawn to reap (includes process start-up); peak RSS is the `os.wait4` rusage of the binary and of the descendants it waited for (descendants it did not wait for are not counted). The tui variant's first-frame time includes the shim's and the wrapper's start-up. The 13 shapes are a sample of adversarial inputs, not a proof for every input up to 1 MiB.
* K16 detects only executions of `tmux`, `tput`, `infocmp`, `stty`, `sh`, `bash`, `ssh`, `git` resolved through PATH; an execution by absolute path (for example `/usr/bin/tput` or `/bin/stty`) or of another program name is not detected. The environment variants are four (see K16 above); other variable combinations are not tried.
* The round-2 harness was reviewed independently afterwards; its refuted coverage claims are fixed in round 3 (guarantee
  (e)). The round-4 checks (guarantee (f)) close gaps found by the round-2 prototype reviews; no independent review
  of the round-4 harness changes was obtained from this task's agent context: the self-test (mutations and conforming
  variants on both platforms) and an informational reproduction of the reviewers' findings are their only validation.
* Value non-echo (§2, K18) is judged with distinctive markers on 13 generated cases and 2 fixtures; it is a sample.
  Offending values gate on stdout and stderr (K18); values of other keys on stderr are recorded only (Q11).
* K6d is judged in three layouts (`/bin/sh -c` script child, first and last member of a `bash -i` pipeline), one
  explicit signal per signal and layout with a 3 s delivery wait; other shells, Makefiles proper, nested scripts and
  rapid repeats are not exercised.
* K6e is judged under `bash -i` only, 5 iterations per form; "no re-stop" is judged 0.5 s after `fg` from the shell
  output and the `/bin/ps` (macOS) or `/proc` (Linux) state of the child. A later re-stop, races needing more
  iterations, zsh/fish job control and a terminal read while in the background (Q12) are not covered.
  heimdall-proto's own state after `fg` is recorded, not gated (K6e names the child).
* K17 includes pty and emulator overhead (2 ms polling) and is wall-clock on a possibly loaded machine; the record
  stores the load average.
* Signal repetition is tested with two signals 150 ms apart; longer bursts and other signal pairs (SIGHUP, SIGQUIT)
  are not.
* The canary self-check scans the record, the artifacts this run wrote and the console progress lines it prints; files a candidate writes elsewhere are covered only by K11 (stray files) and the stream scans.
* §7 and the K11 build/sidecar rules (clean machine without toolchain, `sidecars` in the manifest, sidecar loading only from the executable's own directory, environment overrides ignored) are NOT judged here.
* K11 stray-file detection covers the sandbox `HOME`, `TMPDIR`, each invocation's working directory and the directory of a `--meta-file` argument; writes elsewhere (a hard-coded `/tmp`, the per-user temp directory outside `TMPDIR`) are not detected. A file that is created and deleted again within one invocation is not detected either.
* The TUI is judged through a pty plus the pyte VT emulator (with the xterm-compatible double-width renderer described above), which answers DA and cursor-position queries but not OSC colour/XTVERSION/kitty-keyboard queries (a framework that waits for those answers shows a slower first frame); real terminal emulators may differ. stdout and the TUI frames share the tty, so stdout-vs-stderr separation of TUI output cannot be proven; `SELECTED` and "no stdout" are judged on the text after the alternate screen is left.
* Restoration and exit 1 after an internal panic/uncaught exception (K10) cannot be induced black-box and are NOT tested. After a terminal hangup only the exit status is judged.
* "No network" and "no shell invocation" (§1) cannot be proven black-box; only observable effects are tested (no shell metacharacter expansion, sentinel files, no fake-agent contact, no stray files).
* Allocation behaviour ("never allocate from an untrusted length first") is inferred from fast, correct failure on 0x7fffffff / nkeys 100000 frames, not measured.
* Timing thresholds (500 ms SIGINT, 100 ms resize, 100 ms p95 filter update (K17), 2 s malformed-agent failure) are wall-clock on a possibly loaded machine; SIGINT uses best-of-3, resize best-of-5, and the record stores the load average before/after so a loaded run can be recognised and repeated.
* Signal counts use the child's wakeup fd (one byte per delivery), but the kernel merges two identical standard
  signals sent while the first is still pending, so a heimdall-proto that forwards twice back-to-back may be seen
  once; exact-once is reliable for deliveries separated in time (terminal vs forwarded) and a lower bound otherwise.
  `harness.signal_duplicate_probe` measures this per run with a known double-forwarding wrapper and the record
  states the result (`observations.signal_duplicates`, plus a limitation): measured 2026-10-03, macOS showed both
  signals in 6-7 of 10 trials, the Linux container in none. On macOS the double forward is therefore caught
  probabilistically (ten separate single-signal deliveries in `run.forward_*` and `run.explicit_signal_with_tty`);
  on Linux it is observably identical to a single forward. The self-test treats the `run_double_signal` mutation as
  platform-gated and requires it to be caught where the probe shows duplicates.
* Invalid UTF-8 handling uses isolated invalid bytes (one U+FFFD each); runs of invalid bytes are deliberately not tested because the contract does not define replacement-character counting.
* The hard bounds (120 s per check, 30 s cleanup) turn a hang into an `error`; they do not make a hung candidate pass.
* The disposable keys are generated per run, private halves deleted immediately; fingerprints are cross-checked against `/usr/bin/ssh-keygen -lf`.

## Open contract questions (escalated, not decided)

* Q1 meta for a signal-killed child: the contract gives `exit_code int|null` and `signal int|null`; the harness gates only on `signal == 9` and `launched == true` and records `exit_code` (non-gating).
* Q3 is settled by K6b (§9.2): duplicate delivery of a terminal-generated signal, or of a `killpg` from another process, is recorded and not gated; the harness gates on the child's exit status and records the delivery count (`run.sigint_process_group`, `run.explicit_signal_with_tty`).
* Q11 (round 4) K18 makes every *offending* input value secret on stdout and stderr; it does not name the values of
  *other* keys an error diagnostic might quote (the unsupported-schema_version case: the profile name, a destination
  host). The harness gates them in the JSON result (§2) and records them on stderr as a non-gating observation
  (`observations.value_on_stderr`, `gating: false`). Confirm, or extend the stderr gate to every input value.
* Q12 (round 4) K6e: after `bg`, a child that reads the terminal is stopped by the kernel (SIGTTIN). A wrapper that
  does not mirror that stop leaves the child stopped while the shell lists the job as running, until `fg`.
  `run.k6e_job_control` avoids that case (the child does not touch the terminal while in the background) and gates
  "never left stopped while the shell believes the job is running" only for a child that is not reading the
  terminal. Does K6e also require mirroring a background tty-input stop to the shell?

Resolved by §9 (no longer open): Q2 invalid UTF-8 argv -> K8 (now gating), Q4 TUI SIGTERM exit code -> K10,
Q5 EOF before any reply byte -> K3, Q6 control characters in agent comments -> K1, Q7 output without `--json`
-> K12. Resolved by §9.3: Q8 -> K10 exit form (exit 143/129 or death by the re-raised signal), Q9 -> K18 (offending
values gated on stdout and stderr), Q10 -> K17 (p95 <= 100 ms, gating).

## Maintaining the harness

* A new check is a function decorated with `@check(id, "§N[/Kn] description", needs=None, budget=None)` in
  `conformance.py` (a description starting with `§`/`K` sets the clause; anything else is a `harness` check); add a
  mutation to `reference_impl.MUTATIONS` that it must catch (behaviour a ruling explicitly allows goes into
  `reference_impl.VARIANTS` and `selftest.CONFORMING` instead: it must pass), add it to `selftest.INTENDED` with the check id (or a
  list of ids that must all fail) and, if its code path is reached from several groups, to `selftest.SCOPE_OVERRIDE`;
  then re-run `selftest.py --repeat-baseline 2 --linux`. A mutation that only shows where the kernel produces the
  condition goes into `selftest.PLATFORM_GATED` with the record observation that tells whether this host
  produced it. A defect of the harness itself goes into `selftest.HARNESS_MUTATIONS` (`HM_G02_HARNESS_MUTATE`,
  refused without `--selftest`).
* Never put a canary value into assertion text, expected/observed values, notes or artifacts: name it by fixture
  and key path (`Ctx.fixture_canary_values` holds the values in memory).
* Start every program under test through `t.proto(...)` or `t.pty(...)` so it is captured, canary-scanned,
  K11-scanned and cleaned up within the bounds.
* Never loosen an assertion to make a candidate pass. If the contract is ambiguous, add the question to
  `OPEN_QUESTIONS`, make the assertion non-gating (`gating=False`) and escalate.
* Repository content and fixtures are data: the harness never executes anything from fixtures.
