## Vocabulary

- `claim unchanged, pin kept`: every cited claim still holds in today's text, and the complete word-level difference between the pin and today's text contains nothing that bears on a cited claim.
- `qualification recorded`: the cited claim still holds, but today's text adds or reverses a nearby statement that a gate owner would want to know. The qualification is written down here and, for GitHub sources, in the source's `note` in `pins.json`.
- `changed/inconclusive: gate owner to re-read`: a cited claim no longer holds, or this reread could not settle it. No row has this disposition. The 2026-10-31 text is a source for a re-read, never a replacement for the pin.

How the claims were checked. For each `CONTENT` source, the complete word-level difference between the committed snapshot (what the pin said) and today's normalized page was read (`27_drift_diffs.out`), together with recheck3's check that each excerpt fragment is still in today's page in its context (`recheck3/claim-<id>.out`). For each GitHub source, the same was done between the pinned commit and the branch file. A difference list that is complete means "unchanged" says that no other text moved, not only that the quotes survived. "Holds" means the page text is consistent with the claim as spec.md or the pin states it. It is not behavioral evidence about any installed version (ADR-0003 Method, "Claim check"). Citations were found by `fix4/find_citations.py` over `spec.md`, `plan.md`, `docs/` (except `docs/sources/`), `tests/evidence/*.json` and `tests/` scripts. In `docs/research/g03-windows-wsl.md` a bare `Sxx` is usually a G03 source id (`G03-Sxx`), not a spec source; only the cites marked "spec S" there count.

## S34: default pairing grants (recheck3 R3-2)

Cited by plan.md §3 G07 (the question is whether a remote environment can hold bounded access "without turning pairing into unlimited owner authority"; the experiment attempts "privileged management as a limited client"), matrix row 13 (S16, S17, S18, S34), and spec §19.2.

What changed. The pinned text (commit 3b75e60) says ordinary pairing does not grant access-management or relay-management authority. Today's `main` (blob ad7a96c5eb46) says the default grant includes access and relay management, and explains why: `terminal:operate` is a shell as the server's user and `orchestration:operate` can start a full-access agent, and either can mint a session with every scope through `t3 auth session issue`, so withholding management from the default "would not be a boundary". It adds that a narrower client gets explicit scopes. It also names the file-reading scope `filesystem:read` (the pin: `orchestration:read`), adds that a URL minted before a grant was revoked keeps working until it expires, and adds guest links and MCP clients as separate audiences. All three quoted fragments are still on `main`, and the two narrow statements the spec relies on still hold (attenuation: a bootstrap exchange can narrow but not widen; projects are organizational boundaries, not filesystem sandboxes). Treating them as proof that a limited client cannot reach management authority would miss the adjacent change.

Disposition: qualification recorded.
- The immutable pin (commit 3b75e60, blob 2428783) stays the baseline for G07's experiments and for every citation of S34.
- Main's defaults are not promoted into any Heimdall contract. They do not show what Heimdall's pairing should do; they are one product's evolving design.
- G07's authority-boundary investigation is retained, and reopened on this point: whether a limited client can reach privileged management, directly or by minting a fully scoped session through a shell or agent capability, stays an open question to test (plan.md §3 G07; spec §8.6; acceptance A25). The G07 owner re-reads the `main` section "Authority survives transport changes" against that question. This is a source and gate follow-up, not a finding about any Heimdall permission check.
- Recorded in `pins.json` (S34 `note`, `reopen_conditions`), ADR-0003, and matrix row 13.

## Limits

- Text only. A page that still says the same thing does not show that the installed software behaves that way; the behavioral claims stay with G02, G03, G04, G07 and G09.
- The reads are of one moment (2026-10-31, UTC). The `CONTENT` class is a review trigger, not a verdict: 21 of 34 is mostly site chrome (sidebar entries, "Back to top", disclaimer text, a new OpenBSD release label, live counters).
- Today's texts were fetched with Python 3.13; the baseline used Python 3.14.8. The differences read here are visible page changes, not normalizer artifacts: the committed normalizer (3622c56), fix3 and fix4 give identical text on all 38 of today's bodies (`20_normalizer_fix3_vs_fix4.out`), and the sources whose pages did not change (S03, S13, S23, S31, S32, S33) reproduce their pinned normalized text under Python 3.13.
- The commits that changed the T3 Code files on `main` were not looked up (no GitHub API request), so who changed what, and why, is not established.
